## Globale beperkingen (uit de spec en CLAUDE.md; gelden voor elke taak)

- **Geen secrets in Git, evidence of Scrum4Me.** Postgres-wachtwoorden ontstaan op max2 (`openssl rand -hex 24`), leven alleen in `/home/devdock/dev-docker/.env` (0600) en de container-env; nooit op de Mac-schijf, nooit in transcripten of bewijsbestanden; agents gebruiken nooit `db url --reveal`, `docker … inspect dev-postgres` of `exec … printenv` (spec §6.1, §7). **Enige uitzondering:** de helper zelf leest `DEV_PASSWORD` via `docker exec dev-postgres printenv DEV_PASSWORD` in procesgeheugen (spec §6.2), en de **Secretscan** (eigen sectie hieronder) gebruikt dezelfde route per bewijscommit; de waarde gaat daar uitsluitend via de omgeving naar één `perl`-aanroep (nooit in argv, geen `xargs`), over de **gestagede blobs** in de **max2-checkout**, met leegte- en bestandscontrole en onderscheid LEK/schoon/FOUT. **Een treffer van welke scan ook wordt nooit met inhoud geprint** (`git grep -q`/`-l`, `grep -q`; nooit `-n` zonder `-l`): spec §7 verbiedt secrets in transcripten en tool-uitvoer wordt bewaard. Vóór elke commit in de max2-repo draait de sectie Secretscan (in taak 1 alleen het `git grep`-deel, er is nog geen wachtwoord); gecommit wordt precies de gescande staged set. De SSH-doelen `max2-dev:dev-docker-src/` en `max2-dev:dev-docker/backups/` vallen buiten het patroon `//dev:[^*]`; het `ps`-zoekpatroon in het bewijs wordt als `postgresql:[/]/|[/]/dev:` geschreven zodat het patroon zelf niet matcht.
- **Forge is Forgejo.** Push alleen naar `origin`; PR's via de Forgejo-API/`tea`/compare-URL, nooit `gh pr create`. Niet deployen via Forgejo Actions (CLAUDE.md).
- **Productie-engine onaangeraakt.** Geen `docker`-opdracht onder janpeter op max2 behalve de read-only baseline (spec §8 "Baseline"). Nooit de runnercaps verlagen; waiver D7 wordt niet gewijzigd.
- **Headroom (JP-besluit 14-10-2026):** `--floor-gib 12.0`, `X_eff = 12,0 GiB`, budget `min(8, 21,53 − 12,0)` → **8 GiB**; stopregel: één 5 s-steekproef `MemAvailable < 12,0 GiB` (= 12 582 912 kB) → `systemctl --user stop docker` als devdock, budget verlagen volgens spec §8.2 en melden; `< 10,8 GiB` is bovendien de U4-rode lijn van de pool. **Live bewaakt** tijdens de uitrol en de testrun (taak 2 stap 1, taak 4 stap 3), niet alleen achteraf.

- **Beweer niets dat je niet hebt gemeten:** elk "werkt" in het bewijs komt met de opdracht en de uitvoer; een geslaagde `docker info` alleen haalt de acceptatie niet (spec §9).
- **Idempotent:** `bootstrap.sh`, `install-user.sh`, het firewallscript en de helper mogen herhaald draaien zonder een correcte toestand te wijzigen (spec §4).
- **Geen terugval en geen instelbare doelen:** de helper kent één context (`max2-dev`) en één databasehost (`192.168.0.158`), beide hard in het script; geen omgevingsvariabele kan ze verzetten (spec §5.3, §6.1). Tests vervangen alleen programma's op het PATH (`docker`, `ssh`, `nc`), nooit doelen.
- **Hoofdstop na materialisatie:** dit plan autoriseert geen uitvoering.

## Secretscan (per bewijscommit in de max2-repo; taak 1, 2, 4, 5 en 6)

Draait in de **max2-checkout** op branch `feat/dev-docker-host` (taak 3 en 4 werken zelf in de s4m-queue-repo, dus `cd` is verplicht). Drie regels: (1) een treffer wordt **nooit met inhoud geprint** — alleen `-q` of `-l`, nooit `-n` zonder `-l`; (2) gescand wordt de **gestagede inhoud** (de blobs in de index via `git show :<pad>`), niet de werkboom, en gecommit wordt precies die set: tussen scan en `git commit` geen `git add`, geen edit en geen `commit -a`; elke wijziging daarna → opnieuw stagen én opnieuw scannen; (3) de wachtwoordscan is één `perl`-aanroep met de waarde uitsluitend in de omgeving — geen `xargs` (macOS-`xargs` start bij lege invoer niets en vertaalt exit 1 naar 123) en geen batches (één LEK-oordeel over de hele set).

```sh
cd ~/Development/max2 && git rev-parse --show-toplevel && git branch --show-current   # moet feat/dev-docker-host tonen
set -o pipefail
git add -A evidence/dev-docker                                                         # plus eventuele andere bedoelde bestanden
git grep -qE --cached 'postgres(ql)?://dev:[^*]' -- . ':!*.md'; rc=$?
[ "$rc" -eq 1 ] || { echo "FOUT-url rc=$rc"; git grep -lE --cached 'postgres(ql)?://dev:[^*]' -- . ':!*.md'; exit 1; }
git grep -qE --cached '//dev:[^*]' -- evidence/dev-docker; rc=$?
[ "$rc" -eq 1 ] || { echo "FOUT-url rc=$rc"; git grep -lE --cached '//dev:[^*]' -- evidence/dev-docker; exit 1; }
pw=$(docker --context max2-dev exec dev-postgres printenv DEV_PASSWORD) || { echo FOUT-ophaal; exit 1; }
[ -n "$pw" ] || { echo FOUT-leeg; exit 1; }
git diff --cached --name-only -z --diff-filter=d | MASK_RAW="$pw" perl -e '
  $/ = "\0"; my $p = $ENV{MASK_RAW}; my ($n, $hit) = (0, 0);
  while (my $f = <STDIN>) { chomp $f; $n++;
    open(my $h, "-|", "git", "show", ":$f") or die "FOUT-lees $f\n";
    my $c = do { local $/; <$h> }; close($h) or die "FOUT-lees $f\n";
    $hit = 1 if index($c, $p) >= 0 }
  die "FOUT-geen-bestanden\n" unless $n;
  print $hit ? "LEK\n" : "schoon\n"; exit $hit'
rc=$?; unset pw
[ "$rc" -eq 0 ] || { echo "niet committen (rc=$rc)"; exit "$rc"; }
git commit -m '<bericht>'                                                              # zonder -a; daarna push
```

Uitkomsten: precies één regel `schoon` en rc 0 → commit; `LEK` (rc 1) of `FOUT-*` (rc ≥ 2; door `pipefail` ook een fout van `git diff`) → niet committen, eerst herstellen (bestand corrigeren, opnieuw stagen, opnieuw scannen). `git grep`: exit 1 = geen treffer, 0 = treffer, ≥ 2 = fout; beide laatste stoppen de commit en alleen bestandsnamen worden geprint. `--diff-filter=d` laat gestagede verwijderingen weg (geen blob om te lezen). Het wachtwoord is hex (spec §4.5), dus de encoded vorm is gelijk aan de ruwe. In taak 1 bestaat nog geen wachtwoord: daar draaien alleen de regels tot en met de tweede `git grep`, gevolgd door de commit.

1. **Komma-decimaal of lege `--floor-gib`** → exit 2 vóór enige mutatie, met de punt-hint; **budget onder 2 GiB** → exit 3 (gate) vóór enige mutatie (taak 1, `bootstrap.sh --check-args`).

### Taak 1 — Host-bundel schrijven en statisch verifiëren (max2-repo)

**Files:** create alle `dev-docker/host/*` uit de tabel, `dev-docker/README.md`, `evidence/dev-docker/pgvector-pg17-entrypoint.md`. Test: `bash -n`, `shellcheck -S warning`, `bootstrap.sh --check-args`, `prune.sh --selftest`, `docker compose config`.

**Interfaces.** Produceert:
- `bootstrap.sh --pubkey-file <pad> --floor-gib <X> --series '<GiB>:<bron>' [--preflight-only] [--check-args]`. Exit 0 ok; **2 = ongeldige invoer** (ontbrekende of niet-numerieke `--floor-gib`/`--series`, komma-decimaal → melding "gebruik een punt als decimaalteken"); **3 = preflight/gate rood** (budget onder 2 GiB, AppArmor-profiel ontbreekt, delegatie ontbreekt, ufw niet default-deny, subuid-range bezet, bestaande afwijkende `devdock`). `--check-args` doet alleen de invoervalidatie en de budgetberekening (draait ook op de Mac); `--preflight-only` doet alle read-only controles op max2 en muteert niets. Uitvoer van beide: `X_eff=<GiB> budget_gib=<n> marge_gib=<n>` plus per controle `OK`/`ROOD <reden>`.
- `install-user.sh` (geen argumenten; idempotent; maakt `.env` alleen als die ontbreekt).
- `dev-docker-firewall.sh` en `recovery-test.sh`: spec §4.4 letterlijk.
- `proof-checks.sh` (root, read-only): print achtereenvolgens `ufw status verbose`, `ufw status numbered`, `iptables-save -t filter`, `iptables -S INPUT | awk '$1 == "-A" {print; exit}'`, `iptables -S dev-docker-in`, `iptables -S INPUT | grep -c -- '-j dev-docker-in'`, `iptables -S INPUT | grep -c dd-recovery-test`, `ss -ltn | grep 55432`, `ss -tn 'sport = :55432'`, `nc -z -w2 100.102.8.64 55432; echo "nc-ts rc=$?"`, `nc -z -w2 192.168.0.158 55432; echo "nc-lan rc=$?"`, `journalctl -t dev-docker-firewall -b --no-pager -o short-iso`, `journalctl -b -u dsh-firewall.service -u owui-firewall.service -u dev-docker-firewall.service -o short-iso --no-pager`, `systemctl show user-<uid>.slice -p MemoryMax -p MemorySwapMax -p CPUQuotaPerSecUSec -p TasksMax`, `cat /sys/fs/cgroup/user.slice/user-<uid>.slice/memory.max`, `memory.peak`, `memory.events` en de `anon`-regel uit `memory.stat`, `docker ps -a --no-trunc --format '{{.ID}}\t{{.Image}}\t{{.Names}}\t{{.CreatedAt}}'` en `docker images --digests --format '{{.ID}}\t{{.Repository}}:{{.Tag}}\t{{.Digest}}'` (productie-engine, read-only), `df -B1 /var/lib/docker /home`; elk blok met kop `## <naam>`; alles naar een met `mktemp` aangemaakt bestand in `/var/tmp/dd-proof/` én stdout. Het script maakt die map met `install -d -m 0755 -o root -g root /var/tmp/dd-proof` en stopt met exit 1 en `FOUT-proofdir` als het pad daarna geen gewone map van root is (`[ -d … ] && [ ! -L … ] && [ "$(stat -c %U …)" = root ]`): `/var/tmp` is sticky maar wereld-schrijfbaar, dus `devdock` zou de map of een symlink vooraf kunnen aanmaken. Na het schrijven `chmod 0644 "$out"` (`mktemp` maakt 0600 en het bestand is van root; de inhoud is geen geheim) en de voorlaatste regel is `OUT=<pad>`; de agent haalt het zonder sudo op met `scp 'max2:/var/tmp/dd-proof/*' evidence/dev-docker/raw/`. **Bewust zonder `set -e`** (de enige uitzondering op de regel in stap 1): elk blok eindigt met `|| true`, een `grep -c` zonder treffer telt als `0`, elke `nc`-status wordt eerst in een variabele gevangen en dan geprint (`nc-lan rc=1` is de verwachte weigering; een uitvoeringsfout van `nc` zelf wordt als `nc-lan FOUT` geprint). **Deadline (macOS heeft geen `timeout`; `perl` is gemeten aanwezig):** functie `with_deadline <sec> <cmd…>` roept een vaste perl-wrapper aan die als **toezichthouder buiten de doelgroep** blijft: (1) `fork`; (2) het **kind** doet `setpgrp(0,0)` (wordt leider van een nieuwe groep) en `exec`'t het commando — stdin, stdout en stderr worden geërfd, dus SQL op stdin bereikt `docker exec -i … psql`; mislukt `exec` (programma ontbreekt), dan `exit 127` — perl gaat na een mislukte `exec` gewoon door, dus die regel is verplicht; (3) de **ouder** doet na `fork` zelf óók `setpgrp($kid, $kid)` (fout genegeerd: EACCES betekent dat het kind al ge-exec't is en de groep dus al bestaat), zodat de groep bestaat vóór `alarm` wordt gezet en een vroege alarm nooit een nog niet bestaande groep treft; dan `alarm <sec>` en `waitpid`; INT en TERM op de ouder worden doorgestuurd als `kill $sig => -$kid` (anders bereikt Ctrl-C het kind in zijn eigen groep niet); bij de alarm-handler: `kill TERM => -$kid, $kid` (groep én kind zelf, voor het geval de groep toch ontbreekt), 1 s, `kill KILL => -$kid, $kid`, `waitpid`, dan **exit 124**; (4) zonder time-out decodeert de ouder de status als `($? & 127) ? 128 + ($? & 127) : ($? >> 8)`, zodat een door een signaal gedood transport nooit als 0 terugkomt.
