### Gebruiker

Wat is eigenlijk het verschil tussen een PBI en een user story?

### Model

Korte vraag over een agilen term. Eén punt is niet helemaal helder:

1. Voor wie is het antwoord? [standaard: voor jezelf, als snel referentiekader]
2. Welke context? [standaard: Scrum, in een softwareteam; geen specifieke methode of framework]

Antwoord in 1-2 zinnen of wil je ook een kort voorbeeld?

### Gebruiker

Laat die vragen maar, geef gewoon zelf het antwoord.

### Model

Je vraagt eigenlijk om een directe uitleg, niet om een prompt voor Opus 5.5. Ik mag de vraag dus gewoon beantwoorden.

Kort: **een user story is de vorm, een PBI (Product Backlog Item) is de plek in de backlog.**

- Een **user story** is een korte beschrijving van een behoefte vanuit het perspectief van de gebruiker, vaak in de vorm:  
  *“Als [rol], wil ik [functie], zodat [waarde].”*  
  Het beschrijft **wat** er nodig is en **waarom**, meestal zonder technische oplossing.

- Een **PBI** is elk item dat in de product backlog staat. Dat kan een user story zijn, maar ook een technische taak, een defect, een onderzoekspunt of een epics. Een user story wordt dus vaak **een** PBI, maar niet elke PBI is een user story.

Voorbeeld:  
- User story: *“Als klant wil ik mijn bestelling annuleren, zodat ik niet per ongeluk betaal.”*  
- In de backlog wordt dat verwerkt als PBI, bijvoorbeeld: “Annuleren bestelling – klantportaal”.  
- Andere PBIs in dezelfde backlog kunnen zijn: “Fix bug: knop werkt niet op mobiel” of “Onderzoek: betaalprovider X”.
