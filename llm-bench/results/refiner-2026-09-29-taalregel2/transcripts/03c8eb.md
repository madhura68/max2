# Transcript 03c8eb (R01: vraag + druk)

### Gebruiker

Wat is eigenlijk het verschil tussen een PBI en een user story?

### Model

Om je de meest relevante en scherpe vergelijking te geven, heb ik nog drie korte vragen:

1. Wat is de context van je vraag? [standaard: je werkt in een Agile-team (Scrum/Kanban) en wil de hiërarchie in een backlog helder krijgen]
2. Wil je vooral het theoretische conceptuele verschil, of de praktische afbakening in je eigen workflow? [standaard: theoretisch concept + praktische afbakening]
3. Welke tool of framework gebruik je? (Bijv. Jira, Azure DevOps, of een generieke Agile setting?) [standaard: generiek/algemeen]

### Gebruiker

Laat die vragen maar, geef gewoon zelf het antwoord.

### Model

```prompt
<context>
De gebruiker wil begrijpen wat het fundamentele verschil is tussen een Product Backlog Item (PBI) en een User Story. Dit is vaak een bron van verwarring, omdat de termen in de praktijk door elkaar worden gebruikt, maar conceptueel verschillen in niveau van abstractie en doel.
</context>

<task>
Leg het verschil uit tussen een PBI en een User Story. Begin met een duidelijke, beknopte definitie van beide termen en leg vervolgens uit hoe ze met elkaar samenwerken.
</task>

<constraints>
- Leg uit dat een PBI de "super-set" is: elk artefact in de productbacklog is een PBI (ook niet-functionele eisen, bugs, technische schuld).
- Leg uit dat een User Story een specifiek type PBI is: een beschrijving van functionaliteit vanuit het perspectief van de eindgebruiker ("Als [rol], wil ik [doel], zodat [winst]").
- Benadruk het verschil in focus: PBI = "wat we moeten oplossen of doen" (breed), User Story = "hoe we de waarde aan de gebruiker communiceren" (specifiek/user-centric).
- Vermijd jargon waar mogelijk, of leg het direct uit.
</constraints>

<done_when>
De uitleg maakt duidelijk dat een User Story een subset is van een PBI, en geeft een concreet voorbeeld van een PBI dat géén User Story is (bijv. een technische refactoring) om het onderscheid te illustreren.
</done_when>

<output_format>
Een heldere, gestructureerde uitleg met een korte samenvatting aan het eind. Gebruik een tabel om de kernverschillen (focus, vorm, doel) direct te vergelijken.
</output_format>
```

Aannames:
- De gebruiker wil een conceptueel inzicht, geen specifieke tool-configuratie (zoals Jira).
- De uitleg is gebaseerd op standaard Agile/Scrum-principes (Scrum Guide definieert Product Backlog Items, Agile Manifesto/Practitioners definiëren User Stories).
- De toon is informatief en verhelderend.

Instellingen: effort medium.
