# Transcript ca3291 (R03: vaag bouwidee)

### Gebruiker

Ik wil een dashboard voor mijn Ollama-modellen op max2.

### Model

Het verzoek bevat een onbekende term ("max2") en mist cruciale context voor een dashboard. Om een scherp prompt te maken, stel ik de volgende vragen:

1. Wat bedoel je met "max2"? Is dit een typfout voor "MacBook" (bijv. M2/M3 chip), een specifieke servernaam, of iets anders? [standaard: MacBook met Apple Silicon]
2. Welke informatie wil je zien op het dashboard? (bijv. actieve sessies, geheugengebruik per model, inferentie-snelheid, logboek van recente requests) [standaard: overzicht van geladen modellen, geheugengebruik en recente activity]
3. Hoe wil je het dashboard gebruiken? Is het een lokale webpagina (bijv. via Streamlit/Gradio), een CLI-tool, of een statische HTML-pagina? [standaard: lokale webpagina via Python/Streamlit]
4. Moet het dashboard live bijwerken (automatisch verversen) of is een statische snapshot bij elke opvraag voldoende? [standaard: live bijwerken via polling elke 5 seconden]

### Gebruiker

Akkoord. Extra: alleen tokens per seconde en VRAM, geen login.

### Model

Duidelijk: een lokaal, zonder login, met focus op **tokens per seconde** en **VRAM**. De "max2" is nog steeds onduidelijk, maar ik ga ervan uit dat het om een machine met een GPU (CUDA) gaat, aangezien VRAM de belangrijkste metrik is. Als "max2" een specifieke servernaam is, kan de prompt daar later nog aangepast worden.

Hier is de prompt:

```
<context>
Ik wil een lokaal dashboard voor mijn Ollama-installatie. Het dashboard moet geen login vereisen en draait op mijn machine met een GPU. De focus ligt puur op prestatie-metrics: tokens per seconde en VRAM-gebruik.
</context>

<task>
Bouw een lokaal web-dashboard (bijv. via Python/Streamlit of Flask) dat real-time de volgende metRICS voor Ollama toont:
1. Tokens per seconde (throughput) per actieve model-sessie of globaal.
2. VRAM-gebruik (in GB) per model en totaal.
</task>

<constraints>
- Geen authenticatie of login-scherm.
- Alleen de twee genoemde metrics tonen; geen logs, geen modelbeheer, geen config-editor.
- Het dashboard moet automatisch verversen (bijv. polling elke 2-5 seconden).
- Gebruik de Ollama API (http://localhost:11434) voor het ophalen van data.
- VRAM-data kan via `nvidia-smi` (op Linux) of een equivalente GPU-tool worden opgehaald.
</constraints>

<done_when>
- Het dashboard start lokaal op en toont live tokens/sec en VRAM-gebruik.
- Bij een actieve Ollama-request is de throughput zichtbaar.
- Bij geen actieve request is de throughput 0 of "n/a", maar VRAM wordt nog steeds getoond als modellen geladen zijn.
</done_when>

<output_format>
- Een complete, draaibare Python-script (of set bestanden) met alle dependencies.
- Een korte installatie- en start-instructie.
- Een screenshot-beschrijving of voorbeeld van hoe het dashboard eruitziet.
</output_format>
```

**Aannames:**
- "max2" verwijst naar een lokale machine met NVIDIA GPU (CUDA), dus `nvidia-smi` is beschikbaar.
- Ollama draait standaard op `localhost:11434`.
- Tokens per seconde wordt berekend op basis van de Ollama API's `/api/generate` of `/api/chat` response times, of via een externe monitor.
- Streamlit wordt gebruikt als framework voor het dashboard (lichtgewicht en geschikt voor lokaal gebruik).

**Instellingen:** effort medium.

Wil je nog iets aanpassen?

### Gebruiker

Voeg nog toe dat het dashboard ook de laadtijd van een model toont.

### Model

Géén, ik voeg dat toe aan de prompt. Hier is de aangepaste versie:

```
<context>
Ik wil een lokaal dashboard voor mijn Ollama-installatie. Het dashboard moet geen login vereisen en draait op mijn machine met een GPU. De focus ligt puur op prestatie-metrics: tokens per seconde, VRAM-gebruik en model-laadtijd.
</context>

<task>
Bouw een lokaal web-dashboard (bijv. via Python/Streamlit of Flask) dat real-time de volgende metrics voor Ollama toont:
1. Tokens per seconde (throughput) per actieve model-sessie of globaal.
2. VRAM-gebruik (in GB) per model en totaal.
3. Laadtijd van een model (tijd tussen het aanroepen van het model en het moment dat het klaar is voor inferentie).
</task>

<constraints>
- Geen authenticatie of login-scherm.
- Alleen de drie genoemde metrics tonen; geen logs, geen modelbeheer, geen config-editor.
- Het dashboard moet automatisch verversen (bijv. polling elke 2-5 seconden).
- Gebruik de Ollama API (http://localhost:11434) voor het ophalen van data.
- VRAM-data kan via `nvidia-smi` (op Linux) of een equivalente GPU-tool worden opgehaald.
- Laadtijd meten: start de timer bij het initiëren van een model-request en stop hem wanneer het eerste token wordt gegenereerd of het model als "loaded" wordt gerapporteerd door Ollama.
</constraints>

<done_when>
- Het dashboard start lokaal op en toont live tokens/sec, VRAM-gebruik en model-laadtijd.
- Bij een actieve Ollama-request is de throughput zichtbaar.
- Bij het laden van een nieuw model wordt de laadtijd (in seconden) weergegeven.
- Bij geen actieve request is de throughput 0 of "n/a", maar VRAM en eventuele laadtijden worden nog steeds getoond.
</done_when>

<output_format>
- Een complete, draaibare Python-script (of set bestanden) met alle dependencies.
- Een korte installatie- en start-instructie.
- Een beschrijving van hoe het dashboard eruitziet, inclusief voorbeeldwaarden voor de drie metrics.
</output_format>
```

**Aannames:**
- "max2" verwijst naar een lokale machine met NVIDIA GPU (CUDA), dus `nvidia-smi` is beschikbaar.
- Ollama draait standaard op `localhost:11434`.
- Tokens per seconde wordt berekend op basis van de Ollama API's response times.
- Laadtijd wordt gemeten vanaf het moment dat een model wordt aangeroepen tot het moment dat het eerste token gegenereerd wordt.
- Streamlit wordt gebruikt als framework voor het dashboard.

**Instellingen:** effort medium.

Wil je nog iets aanpassen?
