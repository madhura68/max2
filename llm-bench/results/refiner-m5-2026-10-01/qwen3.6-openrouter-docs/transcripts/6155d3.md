# Transcript 6155d3 (D04: feit niet in de docs)

### Gebruiker

Laat de harness bij een mislukte job een melding naar ons Slack-kanaal sturen.

### Model



Goed, ik heb de documentatie gelezen. De harness is een standalone Node 22 / TypeScript CLI die IDEA_CHAT- en TASK_IMPLEMENTATION-jobs uitvoert op een lokaal Ollama-model. Er is al logging via Worker Logs (M4), maar geen Slack-koppeling.

Om de prompt scherp te krijgen, vier vragen:

1. **Welke fouten triggeren een melding?** [standaard: alle terminale statussen (`failed`, `timed_out`, `budget_exceeded`) in de worker-modus]
2. **Wat moet de Slack-melding bevatten?** Bijv. job-id, foutcode, foutmelding, model, duur, en een verwijzing naar de trace? Of iets specifieks?
3. **Waar komt de Slack webhook URL vandaan?** [standaard: een env-var zoals `SLACK_WEBHOOK_URL`, gelezen bij start van de worker]
4. **Alleen voor de worker-modus** (echte scrum4me-jobs: IDEA_CHAT en TASK_IMPLEMENTATION), of ook voor standalone `harness run`? [standaard: alleen worker-modus]

### Gebruiker

Akkoord met je voorstellen.

### Model



```
<context>
De scrum4me-harness is een standalone Node 22 / TypeScript CLI die IDEA_CHAT- en TASK_IMPLEMENTATION-jobs uitvoert op een lokaal Ollama-model (worker-modus). Er is al logging via de WorkerLogs-klasse (M4), maar er wordt geen Slack-melding gestuurd bij fouten.

De job-statussen zijn: `pending`, `running`, `completed`, `failed`, `timed_out`, `budget_exceeded`.
</context>

<task>
Voeg Slack-meldingen toe voor elke mislukte job in de worker-modus. Stuur een bericht naar een Slack-kanaal zodra een job de status `failed`, `timed_out` of `budget_exceeded` bereikt.
</task>

<material>
Projectstructuur (belangrijk):
- Entry point: src/harness.ts
- Worker: src/worker.ts — hier worden jobs verwerkt en is de job-status bekend
- Logging: src/worker.ts bevat de WorkerLogs-klasse (M4)
- Config: src/config.ts — om de webhook URL te laden
- Types: src/types.ts — JobStatus, JobRun
- package.json: Node 22, TypeScript 5.7.3
</material>

<constraints>
- Alleen worker-modus: IDEA_CHAT en TASK_IMPLEMENTATION jobs. Niet voor standalone `harness run`.
- Alleen terminal foutstatussen: `failed`, `timed_out`, `budget_exceeded`. Geen melding bij `completed`.
- Geen melding als de Slack-webhook niet is geconfigureerd (geen crash, gewoon skippen).
- Gebruik de native `fetch` API (Node 22 ondersteunt dit) — geen extra dependencies.
</constraints>

<done_when>
- Een nieuwe module `src/slack.ts` bestaat met een `sendJobFailure`-functie die een Slack-message payload stuurt.
- De worker (src/worker.ts) roept deze functie aan bij het verwerken van een mislukte job.
- De webhook URL wordt gelezen uit een env-var `SLACK_WEBHOOK_URL` via de config.
- Als `SLACK_WEBHOOK_URL` niet is gezet, wordt stilzwijgend geskip zonder error.
- TypeScript compileert zonder fouten (`npm run build`).
</done_when>

<output_format>
- De volledige inhoud van de nieuwe bestanden en de gewijzigde bestanden.
- Een korte uitleg van de integratiepunten.
- Een voorbeeld van de Slack-payload die wordt verstuurd.
- Instructies om te testen met een mock webhook (bijv. https://webhook.site).
</output_format>
```

Aannames:
- De `fetch` API is beschikbaar in Node 22 (geen `node-fetch` nodig).
- De Slack-payload volgt de standaard Blocks API-formaat (een title, een description met foutdetails, en een footer met job-id).
- De worker heeft toegang tot het volledige JobRun-object (inclusief `id`, `error`, `model`, `duration`) op het moment van mislukking.
