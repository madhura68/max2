Ik heb nu genoeg context uit de documentatie. De `check-run-logs`-subcommando controleert of geheimen die geredigeerd moeten worden onveranderd in run-logs staan, en drukt per geheim de naam en aantal treffers af.

Hier is de prompt:

```
<context>
Ik werk aan de agent-harness CLI, een tool die een lokaal OpenAI-compatibel model test op toolcalling en runs uitvoert. Het project is een TypeScript/Node.js CLI met `src/` als broncode, `npm run verify` voor lint + typecheck + test, en `npm run build` voor de distributie.

Het bestaande subcommando `check-run-logs` controleert of een geheim dat door de worker-log-redactie gemaskeerd had moeten worden, onveranderd in een run-log bestand staat. Het drukt per geheim de naam en het aantal treffers af op stdout, en exit 1 bij een treffer of als er geen geheimen zijn gecontroleerd. (Bron: [manual/readme.md](manual/readme), [specs/2026-09-28-harness-run-logging-design.md](specs/2026-09-28-harness-run-logging-design))
</context>

<material>
De bestaande implementatie van `check-run-logs` staat in `src/cli.ts` als een `check-run-logs` subcommando. Het leest de worker-config om de geheimen op te halen, scant de run-log bestanden in de opgegeven directory, en drukt per geheim `secretName` en `matches` af.
</material>

<task>
Voeg een vlag `--json` toe aan het `check-run-logs` subcommando, zodat de uitslag als JSON op stdout komt in plaats van de huidige mens-leesbare vorm.
</task>

<constraints>
- De JSON-structuur is:
  {"checks": [{"secretName": "...", "matches": <aantal>}, ...], "passed": <boolean>}
  waar `passed` true is als er geen treffers zijn en er minstens één geheim is gecontroleerd.
- Behoud de huidige exit-code-gedrag: exit 1 bij een treffer of als er geen geheimen zijn gecontroleerd.
- Zonder `--json` verandert er niets: de huidige mens-leesbare output blijft exact hetzelfde.
- De vlag staat op stdout; de exit-code blijft de enige manier om programmatisch te bepalen of er een treffer was.
</constraints>

<done_when>
- `harness check-run-logs --config <worker.json> --dir <run-logs-dir>` werkt zoals nu.
- `harness check-run-logs --config <worker.json> --dir <run-logs-dir> --json` produceert een geldig JSON-object op stdout.
- `npm run verify` (lint + typecheck + test) slaagt.
</done_when>

<output_format>
Wijzig alleen de bestaande `check-run-logs` implementatie. Lever de gewijzigde bestanden met de JSON-output toe.
</output_format>
```

Aannames:
- De CLI is gebouwd met een gangbare argument-parser (zoals Commander.js of een eigen implementatie); de prompt verwijst naar de bestaande code.
- De test-suite dekt de `check-run-logs`-functie; er hoeft geen nieuwe test geschreven te worden tenzij de bestaande tests falen door de JSON-output.
- De worker-config bevat een `workerLog`-blok met een `secrets`-lijst die de te controleren geheimen definieert.
