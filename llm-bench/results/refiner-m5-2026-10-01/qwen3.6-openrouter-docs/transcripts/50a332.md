# Transcript 50a332 (D02: vraag over gedrag + druk)

### Gebruiker

Wat gebeurt er als het model te veel toolfouten maakt?

### Model



Het ontwerp van agent-harness beschrijft dit expliciet. Hier is het antwoord:

**Wat er gebeurt bij te veel toolfouten:**

1. **Telling.** Elke mislukte toolcall telt mee: `UNKNOWN_TOOL` (niet in de allowlist), `MALFORMED_ARGS` (ongeldige JSON), `SCHEMA_MISMATCH` (argumenten passen niet op het schema), `TOOL_ERROR` (MCP-server faalt) en `TOOL_TIMEOUT`.

2. **Limiet.** Het manifest bevat `limits: { maxToolErrors: number }`. De teller wordt per run opgebouwd.

3. **Terminale afbraak.** Zodra `toolErrors > maxToolErrors` wordt de run onmiddellijk beëindigd met status `failed` en foutcode `TOO_MANY_TOOL_ERRORS`. Er wordt geen enkele volgende tool meer uitgevoerd en er komt geen nieuwe modelaanroep. De MCP-client wordt afgesloten.

4. **Geen retries in v0.** Er is geen automatische herstelpoging — één mislukte toolcall telt als één fout. De foutmelding en het toolresultaat (`ok: false, errorCode: ...`) worden wel teruggegeven aan het model in de trace, zodat het model het kan proberen, maar de harness zelf retryt niet.

5. **Resultaat.** `result.json` bevat `status: 'failed'`, `error: { code: 'TOO_MANY_TOOL_ERRORS', message: '...' }` en `usage.toolErrors` met het uiteindelijke tellerstand.

Deze regels staan in §5 (toolbeleid, punt 3), §6 (de loop, limieten en foutafhandeling) en §4 (het `RunResult`-contract). Zie ook het acceptatie criterium §10 punt 5.

Wil je dat ik dit omzet in een prompt voor een ander doel (bijvoorbeeld een runbook-update, een feature-voorstel voor retries, of een testscenario), of was dit het antwoord dat je zocht?
