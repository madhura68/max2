# Transcript 35af40 (D04: feit niet in de docs)

### Gebruiker

Laat de harness bij een mislukte job een melding naar ons Slack-kanaal sturen.

### Model

Ik heb de architectuur en het statusmodel van de harness gelezen. De harness kent de statussen `failed`, `budget_exceeded`, `timed_out` en exit-code 1 bij elke niet-succesvolle run. Slack-notificaties komen niet voor in de bestaande docs.

Drie vragen om de prompt scherp te krijgen:

1. **Welke jobs moeten triggeren?** Alleen harness-jobs die via de worker-pipeline (M3/M4) op max2 draaien, of ook handmatige CLI-runs (`harness run …`) die lokaal op max2 worden gestart? [standaard: alle harness-runs met een terminale status, ongeacht hoe ze zijn gestart]

2. **Wat staat er in de Slack-melding?** Alleen een korte foutmelding, of ook run-id, model, base_url, status (`failed`/`timed_out`/`budget_exceeded`), en een link naar het run-log of de trace? [standaard: run-id, model, base_url, status, foutcode, en een link naar `/worker-logs/harness/max2/…` op het Ops-dashboard]

3. **Hoe moet de notificatie worden verzonden?** Een POST naar een Slack webhook URL (bijv. via `curl` of een Node-module), of via de bestaande scrum4me-workers infrastructuur als dat daar al een mechanisme voor heeft? [standaard: een configurable Slack webhook URL in de harness-config, aangeroepen vanuit de harness zelf bij een terminale status]

### Model

```
<context>
De harness (zie manual/harness.md) is een CLI-tool die AI-modellen test via de M3/M4 worker-pipeline op max2 (zie architecture/max2.md). De harness kent de volgende terminale statussen: `failed`, `timed_out`, `budget_exceeded`, en exit-code 1 (zie architecture/status.md). Er is momenteel geen Slack-notificatie bij mislukte runs.

De worker-pipeline draait harness-runs op max2 en zet de status in het statusmodel. De run-logs zijn beschikbaar op het Ops-dashboard onder `/worker-logs/harness/max2/{run-id}`.
</context>

<task>
Implementeer een Slack-notificatie die automatisch wordt verzonden wanneer een harness-job een terminale status bereikt (`failed`, `timed_out`, `budget_exceeded`, of exit-code 1), ongeacht of de run via de worker-pipeline of handmatig via de CLI is gestart.

De notificatie wordt verstuurd vanuit de harness zelf, zodra de terminale status is vastgesteld.
</task>

<constraints>
- De webhook URL is configureerbaar in de harness-config (bijv. `slack_webhook_url` in de YAML-config).
- De Slack-melding bevat: run-id, model, base_url, status, foutcode, en een link naar `/worker-logs/harness/max2/{run-id}` op het Ops-dashboard.
- De notificatie mag de bestaande run-afloop niet blokkeren of vertragen (asynchrone verzending).
- Als de webhook URL niet is ingesteld, wordt de melding overgeslagen zonder fout.
- Als de Slack-webhook niet bereikbaar is, wordt de fout gelogd maar de run niet afgebroken.
</constraints>

<done_when>
- Een harness-run met status `failed` of `timed_out` triggerd een Slack-melding met alle vereiste velden.
- Een run zonder Slack webhook URL wordt overgeslagen zonder foutmelding.
- De notificatie wordt verstuurd nadat de run een terminale status bereikt heeft.
</done_when>

<output_format>
- Gewijzigde bestanden met diff.
- Korte uitleg waar de notificatie wordt aangeroepen en welke config-velden zijn toegevoegd.
- Voorbeeld van een Slack-melding in JSON-formaat.
</output_format>
```

Aannames:
- De harness heeft een YAML-config-bestand waar een veld `slack_webhook_url` aan kan worden toegevoegd.
- Run-id, model, base_url en foutcode zijn beschikbaar in de harness-output of config tijdens een run.
- Ops-dashboard URL-formaat is `/worker-logs/harness/max2/{run-id}`.
- Max2 heeft netwerktoegang zodat de Slack-webhook kan worden bereikt.
