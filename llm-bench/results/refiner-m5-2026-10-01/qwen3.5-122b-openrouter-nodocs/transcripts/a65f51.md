# Transcript a65f51 (R03: vaag bouwidee)

### Gebruiker

Ik wil een dashboard voor mijn Ollama-modellen op max2.

### Model

Om een helder en werkend prompt voor je dashboard te kunnen schrijven, heb ik nog een paar details nodig:

1. Wat is je hoofddoel met dit dashboard? [standaard: een overzicht van welke modellen actief zijn, hun resourcegebruik en de huidige prompt-gebruik]
2. Op welke manier wil je het dashboard benaderen en wat is de technische omgeving? [standaard: een lokale webinterface (bijv. via Python/Streamlit of Node.js) die je op max2 draait]
3. Welke specifieke functies zijn essentieel? [standaard: modellen starten/stoppen, logs bekijken, en een simpele chat-interface voor testgesprekken]
4. Moet het dashboard al bestaande data visualiseren of ook direct sturing geven aan de Ollama-processen? [standaard: alleen visualisatie en statusbeheer, geen diepe sturing van externe scripts]

### Gebruiker

Akkoord. Extra: alleen tokens per seconde en VRAM, geen login.

### Model

Hier is de definitieve prompt, inclusief jouw aanvullingen over de metrics en de afwezigheid van login.

```xml
<context>
Ik gebruik Ollama op een machine genaamd "max2" en ik wil een lokaal dashboard om de prestaties van mijn LLM-modellen te monitoren. Er is geen behoefte aan authenticatie of beveiliging omdat het dashboard alleen lokaal beschikbaar is.
</context>

<material>
Geen extra documenten. Gebruik de standaard Ollama API en bestaande metrics voor VRAM-gebruik en inferentie-snelheid.
</material>

<task>
Ontwerp en schrijf de code voor een lokaal dashboard dat in real-time twee specifieke metrics weergeeft voor actieve Ollama-modellen op max2: tokens per seconde (snelheid) en VRAM-gebruik (geheugen).
</task>

<constraints>
- Het dashboard moet geen login- of authenticatiemechanisme bevatten (geen wachtwoord, geen API-key prompt bij start).
- Toon alleen de metrics voor "tokens per seconde" en "VRAM-gebruik". Laat andere metrics zoals CPU-gebruik, netwerk of totale query-aantallen achterwege.
- De interface moet lokaal draaien (bijvoorbeeld via een Python Streamlit app of een simpele Node.js server) en direct toegankelijk zijn via een lokale URL.
- Zorg dat de metrics direct uit de Ollama API of systeemprocessen worden gehaald zonder ingewikkelde tussenlagen.
</constraints>

<done_when>
De code is compleet, kan direct gestart worden op max2 zonder extra configuratie, en toont op het scherm de actuele tokens/sec en VRAM voor een draaiend model.
</done_when>

<output_format>
De volledige broncode in één blok (bij voorkeur Python/Streamlit voor snelheid), gevolgd door een korte instructie hoe het te starten op max2.
</output_format>
```

**Aannames:**
- Je hebt Python 3 en de benodigde libraries (zoals `streamlit` en `requests`) geïnstalleerd of bent bereid deze te installeren.
- De Ollama-service draait standaard op `localhost:11434` op max2.
- "max2" is een Linux of macOS omgeving; als dit Windows is, kan de code nog aangepast worden.

**Instellingen:**
- Effort: medium (standaard voor het opzetten van een lokaal script/dashboard).

Wil je nog iets aanpassen, bijvoorbeeld de voorkeur voor een specifieke programmeertaal of framework?

### Gebruiker

Voeg nog toe dat het dashboard ook de laadtijd van een model toont.

### Model

Hier is de aangepaste prompt met de toegevoegde metric voor laadtijd.

```xml
<context>
Ik gebruik Ollama op een machine genaamd "max2" en ik wil een lokaal dashboard om de prestaties van mijn LLM-modellen te monitoren. Er is geen behoefte aan authenticatie of beveiliging omdat het dashboard alleen lokaal beschikbaar is.
</context>

<material>
Geen extra documenten. Gebruik de standaard Ollama API en bestaande metrics voor VRAM-gebruik, inferentie-snelheid en starttijden.
</material>

<task>
Ontwerp en schrijf de code voor een lokaal dashboard dat in real-time drie specifieke metrics weergeeft voor actieve Ollama-modellen op max2: tokens per seconde (snelheid), VRAM-gebruik (geheugen) en de laadtijd van het model (tijd vanaf start tot klaar).
</task>

<constraints>
- Het dashboard moet geen login- of authenticatiemechanisme bevatten (geen wachtwoord, geen API-key prompt bij start).
- Toon alleen de volgende metrics: "tokens per seconde", "VRAM-gebruik" en "laadtijd". Laat andere metrics zoals CPU-gebruik, netwerk of totale query-aantallen achterwege.
- De interface moet lokaal draaien (bijvoorbeeld via een Python Streamlit app of een simpele Node.js server) en direct toegankelijk zijn via een lokale URL.
- Zorg dat de metrics direct uit de Ollama API of systeemprocessen worden gehaald zonder ingewikkelde tussenlagen.
- De laadtijd moet duidelijk zichtbaar zijn, bij voorkeur gemeten vanaf het moment dat het laden wordt gestart tot het model volledig in het geheugen is.
</constraints>

<done_when>
De code is compleet, kan direct gestart worden op max2 zonder extra configuratie, en toont op het scherm de actuele tokens/sec, VRAM en laadtijd voor een draaiend model.
</done_when>

<output_format>
De volledige broncode in één blok (bij voorkeur Python/Streamlit voor snelheid), gevolgd door een korte instructie hoe het te starten op max2.
</output_format>
```

**Aannames:**
- Je hebt Python 3 en de benodigde libraries (zoals `streamlit` en `requests`) geïnstalleerd of bent bereid deze te installeren.
- De Ollama-service draait standaard op `localhost:11434` op max2.
- "max2" is een Linux of macOS omgeving; als dit Windows is, kan de code nog aangepast worden.
- Laadtijd wordt gemeten als de tijd die nodig is om een model volledig in het geheugen te laden na een startcommando.

**Instellingen:**
- Effort: medium (standaard voor het opzetten van een lokaal script/dashboard).
