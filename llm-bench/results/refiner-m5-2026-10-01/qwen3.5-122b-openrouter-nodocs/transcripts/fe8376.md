# Transcript fe8376 (R09: al compleet)

### Gebruiker

Ik wil een prompt voor Claude Code. Doel: een bash-script plus systemd-service en -timer voor Ubuntu 24.04 dat elke nacht om 03:00 de map /srv/backups met rsync naar mijn NAS (nas.local:/volume1/backup) synchroniseert. Het script schrijft naar /var/log/nas-sync.log, heeft een droge-run-optie (--dry-run) en verwijdert nooit bestanden op de NAS. Lever het script en de twee unit-bestanden, plus de commando's om ze te installeren en te testen. Klaar als een droge run zonder fouten loopt.

### Model

Je input is al erg compleet, maar ik heb drie korte vragen om de prompt voor Claude Code scherp te stellen:

1.  **Authenticatie:** Hoe moet het script inloggen op de NAS (ssh-sleutel, wachtwoord in .netrc, of een specifieke gebruiker)? [standaard: SSH-sleutelauthenticatie voor gebruiker 'backup' op de NAS]
2.  **Rsync-opties:** Behalve `--dry-run` en geen verwijderingen, zijn er specifieke rsync-flags nodig (bijv. `--archive`, `--verbose`, `--partial` voor onderbroken transfers)? [standaard: `--archive --verbose --delete-excluded --no-delete`]
3.  **Log-niveau:** Moet het script bij een succesvolle synchronisatie ook iets in de log zetten, of alleen bij fouten en bij droge runs? [standaard: log elke run (succes en mislukking) met een tijdstempel en aantal overgedragen bestanden]

Zodra je deze beantwoordt (of "ok" zegt), lever ik de volledige prompt.

### Model

Hier is de volledige prompt, klaar om naar Claude Code te sturen.

```xml
<context>
Ik beheer een Ubuntu 24.04 server en wil een betrouwbare back-upoplossing bouwen voor de map /srv/backups naar een externe NAS (nas.local:/volume1/backup). De oplossing moet volledig geautomatiseerd zijn via systemd, veilig werken (nooit bestanden op de NAS verwijderen) en voorzien zijn van logging en een droge-run-modus voor testen.
</context>

<material>
Geen extra materiaal nodig; gebruik standaard Linux-utilities en de specifieke paden hieronder.
</context>

<task>
Maak een compleet pakket bestaande uit:
1. Een bash-script (`/usr/local/bin/nas-sync.sh`) dat /srv/backups synchroniseert naar nas.local:/volume1/backup met rsync.
2. Een systemd service-bestand (`/etc/systemd/system/nas-sync.service`).
3. Een systemd timer-bestand (`/etc/systemd/system/nas-sync.timer`) die de service elke nacht om 03:00 start.

Het script moet:
- Een optie `--dry-run` ondersteunen die alleen toont wat er zou gebeuren zonder te schrijven.
- Altijd loggen naar `/var/log/nas-sync.log`, inclusief tijdstempel, status (succes/fout/droog run) en het aantal overgedragen bestanden.
- Gebruik maken van SSH-sleutelauthenticatie voor gebruiker 'backup' op de NAS.
- Strikt verbieden dat bestanden op de NAS worden verwijderd (geen `--delete` naar de bron, of expliciet filteren).
- Geen fouten geven als de NAS offline is, maar wel loggen.

Lever daarnaast de exacte shell-commando's om:
- Het script en de unit-files te installeren met juiste permissies.
- De daemon te reloaden.
- De timer te activeren.
- Een handmatige testrun (zowel droog als echt) uit te voeren.
</task>

<constraints>
- Gebruik geen wachtwoorden in scripts; ga uit van SSH-keys.
- Zorg dat het script exit codes correct hanteert zodat systemd de status kan zien.
- Vermijd `rm -rf` of andere destructieve commands zonder expliciete check.
- Het script moet idempotent zijn en veilig kunnen draaien als de vorige run nog niet klaar was (optioneel: lock-file of wacht op vorige run).
- Gebruik moderne Bash-stijl (optionele variabelen, duidelijke comments).
</constraints>

<done_when>
- De droge run (`--dry-run`) zonder fouten verloopt en de juiste output naar de log schrijft.
- De systemd-unit bestanden syntactisch correct zijn en geladen kunnen worden.
- De timer correct ingesteld is op 03:00 dagelijks.
- Alle benodigde installatie- en testcommando's aanwezig zijn.
</done_when>

<output_format>
Presenteer de oplossing in deze volgorde:
1. Het volledige inhoud van het bash-script.
2. Het volledige inhoud van het .service bestand.
3. Het volledige inhoud van het .timer bestand.
4. Een blok met de commando's voor installatie, configuratie en testen.
5. Een korte uitleg van hoe de authenticatie en beveiliging werkt.
</output_format>
```

**Aannames:**
- SSH-sleutels voor gebruiker 'backup' zijn al gegenereerd en geplaatst op de server en de NAS.
- De NAS accepteert verbindingen via ssh/rsync op de standaard poort.
- De gebruiker heeft sudo-rechten op de Ubuntu server.
