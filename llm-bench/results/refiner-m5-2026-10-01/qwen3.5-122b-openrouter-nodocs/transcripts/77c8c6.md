# Transcript 77c8c6 (R01: vraag + druk)

### Gebruiker

Wat is eigenlijk het verschil tussen een PBI en een user story?

### Model

Om de juiste prompt te maken voor Claude Opus 5.5, heb ik nog een paar details nodig:

1. Voor welk doel wil je dit verschil weten? [standaard: om het concept zelf beter te begrijpen]
2. Wie is de beoogde lezer van het antwoord dat Opus gaat genereren? [standaard: jijzelf, als kennisvergroting]
3. Moet het antwoord zich beperken tot Scrum/Agile context, of ook andere frameworks meenemen? [standaard: puur binnen Scrum-context]
4. In welke vorm wil je het antwoord? [standaard: korte, duidelijke uitleg met een vergelijkingstabel]

### Gebruiker

Laat die vragen maar, geef gewoon zelf het antwoord.

### Model

Ik geef alleen prompts en geen antwoorden zelf; hier is de prompt die je direct aan Claude Opus 5.5 kunt geven:

```xml
<context>
De gebruiker wil het fundamentele verschil begrijpen tussen een Product Backlog Item (PBI) en een User Story binnen de Agile/Scrum context. De uitleg is bedoeld voor eigen kennisvergroting.
</context>

<task>
Leg duidelijk en beknopt uit wat een Product Backlog Item (PBI) is en wat een User Story is, en beschrijf vervolgens het specifieke verschil en de relatie tussen beide.
</task>

<constraints>
- Gebruik geen jargon zonder uitleg.
- Leg uit dat een PBI een overkoepelend begrip is, terwijl een User Story een specifieke type PBI is.
- Vermeld andere voorbeelden van PBIs die geen User Story zijn (zoals bugs, technische taken of epics).
- Geef een concreet voorbeeld van een PBI dat geen User Story is.
</constraints>

<done_when>
Het antwoord definieert beide termen, benoemt de hiërarchische relatie (PBI als container, User Story als type), en geeft ten minste één voorbeeld van een PBI dat geen User Story is.
</done_when>

<output_format>
Een korte, heldere uitleg in lopende tekst, gevolgd door een beknopte vergelijkingstabel met de hoofdpunten.
</output_format>
```

Aannames:
- De context is puur Agile/Scrum.
- De lezer is de gebruiker zelf.
- Er wordt geen diepgaande historische analyse gevraagd, alleen het functionele verschil.

Instellingen: effort low.
