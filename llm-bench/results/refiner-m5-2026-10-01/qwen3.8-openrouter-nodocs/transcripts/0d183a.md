# Transcript 0d183a (R08: agenttaak)

### Gebruiker

Laat Claude Code mijn repo migreren van Jest naar Vitest.

### Model

Vier vragen om de prompt scherp te krijgen:

1. Wat moet er concreet gebeuren? [standaard: alle Jest-configuratie en testbestanden overzetten naar Vitest, zodra alle tests op de nieuwe stack groen draaien]
2. Welke stack en configuratie gebruik je nu? [standaard: TypeScript, React, Jest met ts-jest of babel-jest, configuratie in package.json of jest.config.js]
3. Hoeveel tests en welke mockings/patches zijn er? [standaard: enkele honderden tests, met mocks van node_modules en eventueel jsdom voor componenttests]
4. Mag Claude Code zelfstandig doorwerken en commits maken? [standaard: zelfstandig doorwerken, geen commits; ik review alles zelf]

### Gebruiker

Akkoord met je voorstellen. Het is een TypeScript-project met ongeveer 200 tests.

### Model

```
<context>
Ik werk aan een TypeScript-project met ongeveer 200 tests die nu op Jest draaien (configuratie in package.json of jest.config.js, met ts-jest of babel-jest). Ik wil de hele teststack overzetten naar Vitest.
</context>

<task>
Migreer de repository volledig van Jest naar Vitest: vervang de Jest-configuratie door een Vitest-configuratie, zet alle testbestanden om, en pas mocks, matchers, setup-bestanden en scripts aan zodat de tests op Vitest draaien.
</task>

<constraints>
- Begin met de volledige inventarisatie: alle testbestanden, mocks, setup-bestanden, snapshots en scripts die van Jest afhangen.
- Behoud de testlogica: schrijf tests niet om, zet alleen de API's om (bijv. jest.mock naar vi.mock, toBe naar de Vitest-equivalenten, snapshots omzetten).
- Geen commits maken; alle wijzigingen blijven in de werkmap zodat ik ze zelf review.
- Jest en Vitest mogen tijdelijk naast elkaar bestaan tijdens de migratie; verwijder Jest pas als alles op Vitest draait.
</constraints>

<done_when>
- Alle 200 tests draaien groen via het nieuwe testcommando.
- Er is geen enkele verwijzing naar Jest meer in package.json, config-bestanden of testbestanden.
- Het nieuwe testcommando in package.json (bijv. "test": "vitest") werkt.
</done_when>

<output_format>
Werk door tot de migratie af is. Rapporteer aan het einde: wat er overgezet is, welke bestanden aangepast werden, eventuele tests die niet 1:1 over te zetten waren met uitleg waarom, en het commando om de tests te draaien.
</output_format>

<check_in>
Stop en vraag het mij als je tegen een test of mock aanloopt die niet 1:1 te migreren is (bijv. een mock die op intern Jest-gedrag leunt), en stel dan een oplossing voor voordat je verdergaat.
</check_in>
```

Aannames:
- De repository heeft geen speciale Jest-afhankelijkheden zoals jsdom of custom matchers die apart benoemd moeten worden; die ga je zelf detecteren.
- De tests draaien nu groen vóór de migratie; falende tests die al bestonden, hoef je niet te repareren.
- Er is geen CI die expliciet naar Jest commando's referent; die pas je eventueel ook aan.

Instellingen: effort high (grote, langlopende agentic taak met 200 bestanden). Koppel de repo aan Claude Code zoals gebruikelijk.
