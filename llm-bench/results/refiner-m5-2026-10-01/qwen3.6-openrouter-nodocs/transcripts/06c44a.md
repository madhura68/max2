# Transcript 06c44a (R06: review zonder bestand)

### Gebruiker

Kun je mijn docker-compose op security laten reviewen?

### Model

Om de review zo accuraat mogelijk te maken, heb ik een paar details nodig:

1. Welke bestanden wil je precies laten reviewen (alleen `docker-compose.yml` of ook `Dockerfile`s en eventuele `.env`-bestanden)? [Standaard: alleen de `docker-compose.yml` die je plakt]
2. Draait de applicatie in een productie-omgeving of een ontwikkelomgeving? (Dit bepaalt hoe streng de security-richtlijnen zijn.) [Standaard: productie-omgeving, dus strikte security]
3. Wil je dat ik ook let op best practices voor logging, resource limits en netwerksegmentatie, of focus je puur op kwetsbaarheden? [Standaard: volledige review inclusief best practices]
4. Is er specifieke context over de stack (bijv. welke services draaien, gebruik van volumes, externe APIs)? [Standaard: ik ga uit van de standaard instellingen in je compose-file]

Plak alstublieft de inhoud van je `docker-compose.yml` (en eventueel andere relevante bestanden) in je volgende bericht.

### Gebruiker

Akkoord met je voorstellen. Het is een compose-bestand voor een paar containers op mijn thuisserver.

### Model

Kun je de inhoud van je `docker-compose.yml` plakken?

### Gebruiker

Akkoord met je voorstellen.

### Model

```yaml
<task>
Review de volgende docker-compose.yml op security issues, best practices en potentieel risico's voor een thuisserver-omgeving. Identificeer alle beveiligingsproblemen, geef aan hoe ze verholpen kunnen worden en rangschik ze op ernst.
</task>

<material>
Hier komt de docker-compose.yml inhoud
</material>

<constraints>
- Focus op security issues zoals overbodige privileges, niet-versleutelde communicatie, hard-coded credentials, ontbrekende resource limits, en onnodige host-netwerk toegang.
- Let ook op best practices voor logging, netwerksegmentatie en volumes.
- Vermeld geen algemeenheden over Docker security die niet van toepassing zijn op deze specifieke configuratie.
</constraints>

<done_when>
- Alle security issues zijn geïdentificeerd met een duidelijke uitleg en remediatie suggestie
- Issues zijn gerangschikt op ernst (hoog, medium, laag)
- Aanbevelingen zijn concreet en uitvoerbaar
</done_when>

<output_format>
Een gestructureerde review met:
- Samenvatting van belangrijkste bevindingen
- Gedetailleerde bevindingen per issue (ernst, beschrijving, locatie in compose-file, remediatie)
- Algemene aanbevelingen voor verbetering
</output_format>
```

Aannames:
- De docker-compose.yml is voor een thuisserver met een paar containers
- Er is geen specifieke productie-omgeving
- De review richt zich op security en best practices

Instellingen: effort medium.
