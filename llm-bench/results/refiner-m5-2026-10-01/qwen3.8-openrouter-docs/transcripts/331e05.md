### Model



```
<context>
In de repo agent-harness staat het commando `harness check-run-logs --config <worker.json> --dir <run-logs-dir>`. Het controleert of een geheim dat de redactie hoort te maskeren onveranderd in een run-log staat, en drukt per geheim alleen de naam en het aantal treffers af, nooit een waarde. Exit 1 bij een treffer, of als er geen enkel geheim gecontroleerd is; anders exit 0. Zie voor de achtergrond de sectie "Run-logs in Worker Logs" in `README.md` en de spec `docs/specs/2026-09-28-harness-run-logging-design.md`. Ik wil de uitslag machineleesbaar kunnen opvangen in een script, zonder de menslezbare output te breken.
</context>

<task>
Voeg aan `harness check-run-logs` een vlag `--json` toe: met die vlag komt de volledige uitslag als één geldig JSON-object op stdout, in plaats van de menslezbare regels. Zonder de vlag blijft het gedrag en de output exact zoals nu. Werk ook de README bij met de nieuwe vlag.
</task>

<constraints>
- Het JSON-object bevat: één algeheel statusveld, en per geheim de naam, het aantal treffers en de paden van de bestanden waarin het voorkomt.
- De waarde van een geheim komt nooit in de JSON, in stdout of in stderr, net als nu.
- Met `--json` is stdout uitsluitend het JSON-object; alle diagnostische en foutmeldingen gaan naar stderr.
- De exit codes veranderen niet: exit 1 bij een treffer of als er geen enkel geheim gecontroleerd is, anders exit 0 — ook met `--json`.
- Niet doen: andere onderdelen van de CLI of het redactiegedrag aanpakken.
</constraints>

<done_when>
- `npm run verify` (lint + typecheck + test) is groen.
- Er is een test die de JSON-output op een fixture run-log vastlegt: het object parseert met `JSON.parse`, bevat per geheim naam, aantal treffers en bestandspaden, en de waarde van het geheim komt nergens in de output voor.
- Zonder `--json` is de output byte-voor-byte gelijk aan de oude.
</done_when>

<output_format>
De code wijzigingen, de nieuwe test, en in de README één regel toevoegen in het bestaande `check-run-logs`-blok van de sectie "Run-logs in Worker Logs" die `--json` noemt en uitlegt dat de uitslag als JSON op stdout komt.
</output_format>
```

Aannames:
- De README staat in `README.md` in de repo-wortel (zoals de doclink in de productdoc `manual/readme` suggereert); pas het pad aan als het in de repo anders heet.
- "Statusveld" is een simpel algeheel veld (bijv. `ok`/`leak`/`no-secrets`); de exacte naam mag Claude Code kiezen in lijn met de bestaande code.
- Bestaande tests voor `check-run-logs` blijven groen en worden niet aangepast.
