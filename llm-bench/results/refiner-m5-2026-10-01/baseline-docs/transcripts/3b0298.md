# Transcript 3b0298 (D01: bouwtaak met docs)

### Gebruiker

Laat Claude Code een vlag --json toevoegen aan harness check-run-logs, zodat de uitslag als JSON op stdout komt.

### Model

Ik heb de context uit de documentatie opgehaald (manual/readme, runbook idea-chat-worker, spec M4). Drie vragen om de prompt af te ronden:

1. Wat moet de JSON bevatten? [standaard: spiegel van de huidige tekstoutput — per geheim de naam, het aantal treffers en of de waarde korter is dan 8 tekens, plus een topniveau-telling van het aantal gecontroleerde geheimen; nooit een waarde]
2. Moet de standaardoutput zonder de vlag byte-identiek blijven (backward compat)? [standaard: ja, en de exitcodes 0/1 veranderen niet]
3. Moet de doco ook mee worden aangepast (manual/readme en het runbook)? [standaard: ja, kort — de voorbeeldopdracht in readme en runbook verrijken met `--json`]

Antwoord bijv. "1 ok, 2 ok, 3 ok" of pas aan.

### Gebruiker

Akkoord met je voorstellen.

### Model

```
<context>
Ik werk in het repo van bench-agent-harness. De opdracht `harness check-run-logs` doorzoekt run-logs naar secret-waarden en eindigt met exit code 0 (geen treffers) of 1 (treffers). De chat-worker en andere automatiseringen moeten de uitslag machine-leesbaar kunnen verwerken, dus ik wil een JSON-modus. Lees vóór je begint de bestaande implementatie van het commando en de documentatie: manual/readme, runbooks/idea-chat-worker en specs/M4 (via de docs-tools). Volg de bestaande code- en doco-conventies van het project.
</context>

<task>
Voeg aan `harness check-run-logs` een vlag `--json` toe die de uitslag als JSON op stdout schrijft, in plaats van de huidige tekstoutput.
</task>

<constraints>
- Zonder `--json` blijft de bestaande stdout byte-identiek; de exit codes 0/1 veranderen in beide modi niet.
- JSON-schema: object met `"checked_secrets"` (aantal gecontroleerde secret-waarden) en `"secrets"` (lijst van objecten met `"name"` (naam van het geheim), `"matches"` (aantal treffers in de logs) en `"short_value"` (true als de waarde korter is dan 8 tekens)).
- Geen enkele secret-waarde komt in de JSON (ook niet gedeeltelijk of gehashd); alleen naam, teller en de booleaan.
- `--json` mag niet combineren met andere output-vlaggen van het commando; bij onbekende vlagen gelden de bestaande foutregels.
- Pas de documentatie aan: verrijk de voorbeeldopdracht in manual/readme en in runbooks/idea-chat-worker met een `--json`-voorbeeld, en beschrijf het JSON-schema in één alinea in de readme.
</constraints>

<done_when>
- `harness check-run-logs` zonder vlag produceert exact dezelfde stdout en exit code als vóór de wijziging.
- `harness check-run-logs --json` produceert geldige JSON op stdout (controleerbaar met `jq .`), met het schema hierboven, en bevat geen secret-waarde.
- De exit code bij `--json` is 0 zonder treffers en 1 met treffers.
- De voorbeeldopdrachten in readme en runbook zijn aangepast.
</done_when>

<output_format>
De code-wijziging, plus een voorbeeld van de JSON-output voor een run met en zonder treffers, en de aangepaste doco-fragmenten.
</output_format>

<check_in>
Dit is een lokaal, omkeerbaar wijziging: ga door zonder tussentijdse bevestiging, tenzij je tegen een tegenspraak in de bestaande code of doco loopt die het JSON-schema raakt.
</check_in>
```

Aannames:
- De bestaande tekstoutput en exit codes (0/1) zijn zoals in de doco beschreven; de vlag voegt alleen een modus toe.
- Het project heeft geen verplichte test-suite; verificatie gebeurt via de twee handmatige checks in <done_when>.
- `--json` is de enige nieuwe vlag die dit commando nodig heeft.

Instellingen: effort medium. Koppel niets toe — Claude Code heeft zelf toegang tot de bestanden en docs.
