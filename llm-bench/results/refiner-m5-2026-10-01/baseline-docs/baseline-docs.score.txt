> Model, beurt 1:
>
> Het harness stopt de run onmiddellijk en markeert deze als **`failed` met de code `TOO_MANY_TOOL_ERRORS`**.
>
> Concreet (zie [v0-ontwerp §6](specs/2026-09-26-agent-harness-v0-design#6-de-loop-limieten-en-foutafhandeling) en [M4-runbook](runbooks/idea-chat-worker#praktijkbewijs-m4-2026-09-29)):
>
> 1. **Directe stop.** Zodra `toolErrors > maxToolErrors` wordt een terminale beslissing genomen. Er wordt geen enkele modelaanroep of tooluitvoering meer gedaan.
> 2. **Afsluitblok.** Het run-log schrijft één keer: `ERROR TOO_MANY_TOOL_ERRORS: … <N> tool errors exceed maxToolErrors=<N>`, gevolgd door `exit code=1`.
> 3. **Ops-dashboard.** De ingest-tick neemt de run op met status `error` en `error_summary` die de foutcode bevat.
> 4. **Triage.** De bestaande triage-pickup vangt de run (die kijkt naar tool-resultaten met `is_error`), en produceert een `WorkerInsight` met root cause en suggestie.
>
> In de productieproef van 30 september deed het model drie keer `get_product_doc` op niet-bestaande kopjes; `maxToolErrors=2` was de grens, de run eindigde met `ERROR TOO_MANY_TOOL_ERRORS: 3 tool errors exceed maxToolErrors=2`.
>
> Wil je hier nog iets aan toevoegen of aanpassen?

> Model, beurt 2:
>
> Het antwoord staat in [specs/2026-09-26-agent-harness-v0-design](specs/2026-09-26-agent-harness-v0-design#6-de-loop-limieten-en-foutafhandeling):
>
> 1. **De run stopt direct.** Zodanig `toolErrors` de waarde van `maxToolErrors` overschrijdt, wordt de run onmiddellijk beëindigd. Er worden geen extra modelaanroepen of tool-uitvoeringen meer gedaan.
