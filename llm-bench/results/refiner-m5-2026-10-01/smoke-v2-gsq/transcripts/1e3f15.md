# Transcript 1e3f15 (R06: review zonder bestand)

### Gebruiker

Kun je mijn docker-compose op security laten reviewen?

### Model

Kortom om de prompt scherp te krijgen:

1. Hoe geef je het bestand aan? [standaard: je plakt de volledige docker-compose.yaml in het gesprek]
2. Welk profiel moet de review hebben? [standaard: security-architect, gericht op misbruik van container-escape, netwerk en secrets]
3. Welke context mag ik erbij nemen? [standaard: geen, alleen wat in het bestand staat]
4. Welk formaat wil je als resultaat? [standaard: lijst per bevinding met ernst (kritiek/hoger/middel/laag), locatie in het bestand, risico en concrete fix; afsluitend een korte samenvatting]

### Gebruiker

Akkoord met je voorstellen. Het is een compose-bestand voor een paar containers op mijn thuisserver.

### Model

```
<context>
Ik heb een docker-compose-bestand voor een paar containers op mijn thuisserver. Ik wil weten hoe veilig het is voordat ik het gebruik.
</context>

<material>
[PLAK HIER JE VOLLEDIGE DOCKER-COMPOSE.YAML]
</material>

<task>
Review dit docker-compose-bestand als security-architect en rapporteer alle beveiligingsproblemen die je vindt, inclusief subtiele risico's zoals onnodige privileges, host-volumes, netwerkconfiguratie, secrets-handeling en image-keuze.
</task>

<constraints>
- Beoordeel alleen wat in het bestand staat.
- Vermeld bij elke bevinding de exacte locatie in het bestand (service, lijn of parameter).
- Geef voor elke bevinding: ernst (kritiek, hoog, middel, laag), het risico in één zin, en een concrete fix.
- Rapporteer ook zaken die je niet zeker kunt beoordelen zonder extra context, in plaats ze te negeren.
</constraints>

<done_when>
Elke gevonden bevinding heeft een ernst, locatie, risico en fix. Er is een korte samenvatting aan het eind met de drie belangrijkste aandachtspunten.
</done_when>

<output_format>
Een geordende lijst van bevindingen, van hoogste naar laagste ernst, gevolgd door de korte samenvatting.
</output_format>
```

Aannames:
- Het bestand is een standaard docker-compose.yaml zonder referentie naar een aparte .env of secrets-bestand.
- De containers draaien op een Ubuntu/Debian-achtige host met standaard Docker-instellingen.
- Ik mag ook bestaande best-practices noemen, niet alleen wat letterlijk in het bestand staat.

Instellingen: effort medium. Plak je docker-compose.yaml in het <material>-blok.

Wil je nog iets aanpassen?
