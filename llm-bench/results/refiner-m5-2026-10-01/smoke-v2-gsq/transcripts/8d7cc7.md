# Transcript 8d7cc7 (R09: al compleet)

### Gebruiker

Ik wil een prompt voor Claude Code. Doel: een bash-script plus systemd-service en -timer voor Ubuntu 24.04 dat elke nacht om 03:00 de map /srv/backups met rsync naar mijn NAS (nas.local:/volume1/backup) synchroniseert. Het script schrijft naar /var/log/nas-sync.log, heeft een droge-run-optie (--dry-run) en verwijdert nooit bestanden op de NAS. Lever het script en de twee unit-bestanden, plus de commando's om ze te installeren en te testen. Klaar als een droge run zonder fouten loopt.

### Model

Even checken; dit is een buildtaak voor Claude Code. Ik stel een paar vragen, dan geef ik de definitieve prompt.

1. Moet het script bij een mislukte rsync (bijv. NAS onbereikbaar) automatisch opnieuw proberen, of loggen en afsluiten? [standaard: geen retry, wel een duidelijke foutmelding in het logbestand en een niet-null exit code]
2. Hoeveel ruimte en bestandsgrootte is er op /srv/backups? [standaard: enkele GB tot tientallen GB, geen extreme grootte, rsync met --delete-never gedrag via --update of expliciet zonder --delete]
3. Moet de systemd-timer exact op 03:00 of mag hij binnen een klein venster draaien (bijv. 03:00–03:10) om overlapping te voorkomen? [standaard: OnCalendar=*-*-* 03:00:00 met Persistent=true, geen venster]
4. Wil je dat Claude Code ook een korte testcommando-set levert voor droge run én een echte eenmalige run voor controle? [standaard: ja, inclusief systemctl commands en een test met --dry-run]

### Model

```
<context>
Ik gebruik Ubuntu 24.04 en wil een betrouwbare nachtelijke synchronisatie van /srv/backups naar mijn NAS op nas.local:/volume1/backup. Het moet draaien via systemd, een droge-run-optie hebben, nooit bestanden op de NAS verwijderen, en loggen naar /var/log/nas-sync.log.
</context>

<task>
Maak voor Claude Code een bash-script, een systemd-service-unit en een systemd-timer-unit die elke nacht om 03:00 /srv/backups met rsync synchroniseert naar nas.local:/volume1/backup.
</task>

<constraints>
- Het script moet een --dry-run-optie hebben die rsync in droge moduultest uitvoert zonder bestanden te wijzigen.
- Het script mag nooit bestanden op de NAS verwijderen. Gebruik daarom geen --delete.
- Schrijf alle uitvoer naar /var/log/nas-sync.log.
- Bij een fout, zoals NAS onbereikbaar, moet het script een duidelijke foutmelding loggen, een niet-null exit code teruggeven, en niet automatisch opnieuw proberen.
- De timer moet op 03:00 draaien met Persistent=true.
- Lever ook de installatiecommando's en testcommando's op, inclusief een droge run.
</constraints>

<done_when>
Een droge run van het script zonder --dry-run-fouten loopt succesvol af en de twee systemd-unit-bestanden plus installatiecommando's zijn compleet.
</done_when>

<output_format>
Lever in één antwoord:
1. het volledige bash-script;
2. het volledige systemd-service-unitbestand;
3. het volledige systemd-timer-unitbestand;
4. de exacte commando's om de bestanden te installeren, de timer te activeren en te testen;
5. een korte testprocedure voor --dry-run.
Gebruik codeblokken per bestand/commando en schrijf in het Nederlands.
</output_format>
```

Aannames:
- De NAS is bereikbaar via SSH als nas.local en het pad /volume1/backup bestaat al.
- rsync is geïnstalleerd op de Ubuntu-host.
- De synchronisatie mag bestanden op de NAS overwrites, maar mag nooit verwijderen.
- Het logbestand wordt door het script zelf aangemaakt of bijgeschreven.
- Er is geen extra authenticatie vereist buiten het bestaande SSH-setup op de host.
