# Transcript 02cac4 (R03: vaag bouwidee)

### Gebruiker

Ik wil een dashboard voor mijn Ollama-modellen op max2.

### Model

Om een scherpe prompt voor Opus 5.5 te schrijven, heb ik wat meer details nodig over wat je precies bedoelt met een "dashboard".

Vier vragen om dit te verduidelijken:

1. Wat moet het dashboard precies doen? [standaard: het visualiseren van actieve modellen, CPU/GPU gebruik van de max2, en de mogelijkheid om modellen te starten/stoppen]
2. Hoe wil je dit dashboard gebruiken? [standaard: een web-interface die via de browser op een ander apparaat in het netwerk toegankelijk is]
3. Welke technologische voorkeur heb je voor de bouw? [standaard: Python met Streamlit of Flask, gebruikmakend van de Ollama API]
4. Moet het dashboard ook interactie met de modellen ondersteunen (een chat-interface), of is het puur voor monitoring en beheer? [standaard: puur voor monitoring en beheer]

Zodra ik je antwoorden heb, maak ik de volledige prompt voor je.

### Gebruiker

Akkoord. Extra: alleen tokens per seconde en VRAM, geen login.

### Model

```
<context>
Ik draai Ollama-modellen op een Mac Studio M2 Max (max2). Om het beheer en de prestaties inzichtelijk te maken, wil ik een lichtgewicht dashboard dat vanuit een browser toegankelijk is voor apparaten binnen mijn lokale netwerk.
</context>

<task>
Bouw een web-gebaseerd dashboard met Python (gebruik Streamlit of Flask) dat via de Ollama API de status van de modellen op de max2 monitort.
</task>

<constraints>
- Focus op monitoring en beheer: toon welke modellen actief zijn en bied de mogelijkheid om modellen te starten of te stoppen.
- Specifieke metrics: toon uitsluitend de snelheid in tokens per seconde (t/s) en het VRAM-gebruik.
- Geen authenticatie: er mag geen login-scherm of gebruikersbeheer aanwezig zijn.
- De interface moet toegankelijk zijn via het IP-adres van de max2 in het lokale netwerk.
</constraints>

<done_when>
Het dashboard start op, kan succesvol verbinden met de lokale Ollama-instantie, en toont in real-time de actieve modellen inclusief hun t/s en VRAM-gebruik zonder dat er om een wachtwoord wordt gevraagd.
</done_when>

<output_format>
De volledige Python-code voor het dashboard, een lijst met benodigde libraries (requirements.txt), en de instructies om de applicatie te starten zodat deze netwerkbreed toegankelijk is.
</output_format>
```

Aannames:
- De Ollama API is reeds geïnstalleerd en draait op de max2.
- De gebruiker is bekend met het draaien van een Python-script in een terminal.
- De netwerkinstellingen van de Mac staan toe dat er verkeer op de gekozen poort binnenkomt.

Instellingen: effort medium.

Wil je nog iets aanpassen aan de prompt?
