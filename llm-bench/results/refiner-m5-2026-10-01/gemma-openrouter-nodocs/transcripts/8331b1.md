# Transcript 8331b1 (R01: vraag + druk)

### Gebruiker

Wat is eigenlijk het verschil tussen een PBI en een user story?

### Model

Om een scherpe prompt voor Opus 5.5 te maken, heb ik drie korte vragen:

1. Voor wie is het antwoord bedoeld? [standaard: voor jouzelf, om je eigen kennis op te frissen]
2. Wil je een theoretische uitleg of juist een praktische gids met voorbeelden van hoe je ze schrijft? [standaard: een combinatie van beide]
3. Moet het antwoord rekening houden met een specifieke tooling, zoals Azure DevOps of Jira? [standaard: geen specifieke tool, algemene Scrum/Agile principes]

Zodra je deze beantwoordt, schrijf ik de definitieve prompt voor je.

### Gebruiker

Laat die vragen maar, geef gewoon zelf het antwoord.

### Model

Ik schrijf alleen prompts en beantwoord de vragen niet zelf. Hier is de prompt voor Opus 5.5:

```
Leg het conceptuele en praktische verschil uit tussen een Product Backlog Item (PBI) en een User Story.

<context>
De gebruiker wil begrijpen hoe deze twee termen zich tot elkaar verhouden binnen een Agile/Scrum framework, om verwarring over de terminologie te voorkomen.
</context>

<task>
Analyseer het verschil tussen een PBI en een User Story. Leg uit of een User Story een type PBI is, of dat het twee verschillende concepten zijn, en hoe ze in de praktijk worden gebruikt.
</task>

<constraints>
- Baseer het antwoord op algemene Scrum- en Agile-principes.
- Vermijd tool-specifieke beperkingen (zoals alleen Jira of alleen Azure DevOps), tenzij ter illustratie.
- Geef concrete voorbeelden van een PBI die geen User Story is (bijvoorbeeld een technisch task of een bug).
</constraints>

<output_format>
Een heldere uitleg in vloeiende paragrafen, ondersteund door een beknopte tabel die de belangrijkste verschillen (doel, vorm, scope) naast elkaar zet.
</output_format>
```

Aannames:
- Het antwoord is bedoeld voor eigen kennisopfrissing.
- Er is een combinatie van theoretische uitleg en praktische voorbeelden gewenst.
- De focus ligt op algemene Agile principes.

Instellingen: effort low.

Wil je nog iets aanpassen?
