### Gebruiker

Wat is eigenlijk het verschil tussen een PBI en een user story?

### Model

Vraag om de prompt scherp te krijgen:
1. In welke context wil je het verschil begrijpen? Bijvoorbeeld: Scrum, agile ontwikkeling, of een specifiek kader zoals SAFe? [standaard: algemeen agile/Scrum context]
2. Voor welk doel heb je de uitleg nodig? Bijvoorbeeld: voor jezelf om te leren, om uit te leggen aan een team, of om het in documentatie te gebruiken? [standaard: voor persoonlijk begrip en teamcommunicatie]
3. Moet de uitleg praktisch zijn met voorbeelden, of vooral theoretisch en definitorisch? [standaard: praktisch met eenvoudige voorbeelden]
4. Hoe lang mag het antwoord zijn? Bijvoorbeeld: een korte samenvatting, een middellange uitleg, of een gedetailleerde vergelijking? [standaard: middellange uitleg van enkele alinea's]

Beantwoord met bijvoorbeeld: "1 ok, 2 voor teamtraining, 3 praktisch met voorbeelden, 4 middellang" of geef je eigen antwoorden.

### Model

Ik schrijf alleen prompts, dus hier is de prompt voor Claude Opus 5.5 om het verschil tussen een PBI en een user story uit te leggen:

<context>
Je wordt gevraagd het verschil uit te leggen tussen een Product Backlog Item (PBI) en een user story in een agile/Scrum context. Het antwoord is bedoeld voor persoonlijk begrip en teamcommunicatie, met een praktische toon en eenvoudige voorbeelden.
</context>

<task>
Leg duidelijk en praktisch uit wat het verschil is tussen een Product Backlog Item (PBI) en een user story, inclusief wanneer elk begrip wordt gebruikt en hoe ze tot elkaar verhouden.
</task>

<constraints>
- Houd de uitleg praktisch en vermijd zuiver theoretische definities zonder toepassing.
- Gebruik eenvoudige, herkenbare voorbeelden uit softwareontwikkeling.
- Stel duidelijk dat een user story een specifieke vorm van een PBI is, maar niet alle PBIs zijn user stories.
- Noem andere soorten PBIs naast user stories (bijv. taken, bugs, technische verkenningen).
- Vermijd jargon zonder uitleg, maar gebruik de juiste termen zoals PBI, user story, epic, en backlog.
</constraints>

<done_when>
Het antwoord bevat:
- Een duidelijke definitie van PBI.
- Een duidelijke definitie van user story.
- Een uitleg van de relatie tussen beide (user story als type PBI).
- Minstens één concreet voorbeeld van een user story.
- Minstens één concreet voorbeeld van een PBI dat geen user story is.
- Geen onjuiste beweringen zoals "alle PBIs zijn user stories" of "user stories zijn alleen voor klantwaarde".
</done_when>

<output_format>
Een middellange uitleg van twee tot drie alinea's in het Nederlands, met een praktische toon en voorbeelden die direct toepasbaar zijn in een Scrum-team.
</output_format>

Je wilt het verschil begrijpen tussen een Product Backlog Item (PBI) en een user story voor je eigen kennis, in een algemene agile/Scrum setting. Je zoekt een praktische, duidelijke uitleg met voorbeelden om het concept te snappen, zonder theoretisch overbodig detail.
</context>

<task>
Leg praktisch uit wat het verschil is tussen een Product Backlog Item (PBI) en een user story, inclusief hoe ze tot elkaar verhouden en wanneer elk begrip van toepassing is.
</task>

<constraints>
- Focus op de praktische relatie: een user story is een specifieke vorm van een PBI, maar niet alle PBIs zijn user stories.
- Geef duidelijke, herkenbare voorbeelden uit softwareontwikkeling (bijv. een feature als user story, een technische taak of bug als ander type PBI).
- Vermijd zuivere theoretische definities zonder toepassing.
- Stel duidelijk dat PBIs alles zijn wat op de product backlog staat, en user stories één manier zijn om klantwaarde te beschrijven.

</constraints>

<done_when>

- Een uitleg dat user stories een type PBI zijn, maar PBIs ook andere vormen kunnen hebben (takens, bugs, technische verkenningen, enz.).
- Minstens één voorbeeld van een user story (bijv. "Als klant wil ik mijn winkelwagen opslaan zodat ik later verder kan winkelen").

</detected_when>
