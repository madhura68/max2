# Transcript 68c1d2 (R08: agenttaak)

### Gebruiker

Laat Claude Code mijn repo migreren van Jest naar Vitest.

### Model

Vier vragen om de prompt scherp te krijgen:
1. Welke programmeertaal en framework gebruikt je repo (bijv. React, Vue, Svelte, vanilla JS/TS)? [standaard: React met TypeScript]
2. Moet de migratie alleen de testbestanden aanpassen, of ook configuratiebestanden zoals jest.config.js, package.json scripts en afhankelijkheden? [standaard: zowel testbestanden als configuratie]
3. Zijn er specifieke Jest-functies die je gebruikt die speciale aandacht nodig hebben (bijv. mocks, setupFiles, testEnvironment, glob patterns)? [standaard: geen speciale functies, standaard Jest-gebruik]
4. Moet Claude Code de wijzigingen direct aanbrengen (committen), of alleen een voorstel doen dat jij eerst kunt reviewen? [standaard: alleen een voorstel doen, geen directe commits]

Laat je antwoord in de vorm "1 ok, 2 ja maar ...", enzovoort, of geef je eigen waarden op. Als je iets niet weet of het standaard wilt, zeg dan gewoon "ok" bij dat nummer.

### Gebruiker

Akkoord met je voorstellen. Het is een TypeScript-project met ongeveer 200 tests.

### Model

```
<context>
Ik heb een TypeScript-project (waarschijnlijk React, maar framework is niet kritisch) met ongeveer 200 Jest-tests. Ik wil de testsuite migreren van Jest naar Vitest zodat ik kan profiteren van Vite's snelle HMR en native ESM-ondersteuning tijdens development.
</context>

<material>
Niet meegeleverd; Claude Code zal de bestaande repo zelf onderzoeken om Jest-configuratie, testbestanden en afhankelijkheden te vinden.
</material>

<task>
Migreer het project van Jest naar Vitest door zowel configuratie als testbestanden aan te passen zodat alle bestaande tests nog steeds slagen onder Vitest.
</task>

<constraints>
- Werk alleen binnen de bestaande repo; voeg geen nieuwe bronbestanden of functies toe buiten de testmigratie.
- Behoud dezelfde test-declaraties (describe, it, test, expect, beforeEach, etc.) waar mogelijk; Vitest is compatibel met Jest's API.
- Update package.json: verwijder Jest-afhankelijkheden, voeg Vitest en eventuele peer-afhankelijkheden toe (bijv. @vitest/ui als dat gebruikt wordt).
- Maak een vitest.config.ts (of .js) aan die vergelijkbare dekking heeft als de oude jest.config.js (modules, testMatch, setup bestanden, environment, enz.).
- Als er Jest-specifieke configuratie is (mocks, setupFiles, testEnvironment, globals, transform), vind dan de Vitest-equivalenten of verklaar waarom iets niet overgezet kan worden.
- Zorg ervoor dat bestaande npm-scripts zoals "test", "test:watch", "test:coverage" blijven werken (pas ze aan naar vitest, vitest watch, vitest run --coverage).
- Laat geen testbewustzijn verloren gaan: elke test die onder Jest slaagde, moet onder Vitest ook slagen.
- Maak geen wijzigingen aan productiebroncode; beperk je tot test- en configuratiebestanden.
</material>
</constraints>

<done_when>
- Alle bestaande tests (ongeveer 200) slagen wanneer uitgevoerd met `vitest run` (of gelijkwaardig npm script).
- De dekking rapporteert vergelijkbare cijfers als voorheen (indien coverage scripts gebruikt worden).
- Het project kan nog steeds worden gebouwd (`npm run build` of gelijkwaardig) zonder fouten die voortkomen uit testwijzigingen.
- Een korte smoke-test van de dev-modus (`vitest` of `npm test` in watch-modus) toont aan dat HMR werkt bij het wijzigen van een testbestand.
</done_when>

<output_format>
Een overzicht van de gewijzigde bestanden:
- Een lijst van toegevoegde, verwijderde en aangepaste bestanden met korte omschrijving per wijziging.
- De volledige inhoud van nieuwe of sterk gewijzigde configuratiebestanden (vitest.config.ts, aangepaste package.json scripts).
- Een voorbeeld van hoe een enkel testbestand er voor en na de migratie uitziet (alleen als er substantiële wijzigingen waren; anders vermeld dat de meeste tests ongewijzigd blijven).
- Instructions voor het uitvoeren van de tests zowel in ontwikkelings- als CI-modus.
</output_format>
<check_in>
Voor het aanbrengen van wijzigingen aan bestanden die buiten de testmappen vallen (bijv. src/setupTests.ts als die wordt meegezet), vraag eerst bevestiging.
</check_in>
```

Aannames:
- Het project gebruikt een standaard mapstructuur waarbij tests naast bestanden staan of in een `__tests__` of `test` map.
- Er worden geen Jest-specifieke transformaties nodig gehad voor bestanden buiten JavaScript/TypeScript (bijv. geen Vue SFCs die jouw transform nodig hebben).
- Het gebruik van Jest-globals (`describe`, `it`, `expect` enz.) kan direct overgenomen worden zonder extra importen in elk testbestand.
- De huidige dekkingstool (waarschijnlijk Jest's eigen coverage) kan vervangen worden door Vitest's ingebouwde coverage of blijft werken via een externe tool zoals c8.

Instellingen: effort medium.
