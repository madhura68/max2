# Transcript 952021 (R03: vaag bouwidee)

### Gebruiker

Ik wil een dashboard voor mijn Ollama-modellen op max2.

### Model

Vier vragen om de prompt scherp te krijgen:
1. Wat bedoel je precies met "max2"? [standaard: een specifieke versie of configuratie van Ollama, bijvoorbeeld een bepaalde hardwarelimiet of modelcapaciteit]
2. Welke informatie moet het dashboard tonen over je Ollama-modellen? [standaard: modelnaam, status (geladen/niet geladen), geheugengebruik, laadtijd, en beschikbare modellen]
3. Wil je dat het dashboard interactief is (bijv. modellen laden/lossen via knoppen) of alleen alleen-lezen? [standaard: alleen-lezen weergave voor monitoring]
4. In welke vorm wil je het dashboard ontvangen? [standaard: een Python-script met Streamlit of Gradio dat lokaal in de browser draait]

Geef je antwoorden in de vorm:  
1 ok, 2 ok, 3 alleen-lezen, 4 Streamlit  
of corrigeer waar nodig met een korte toelichting.

### Gebruiker

Akkoord. Extra: alleen tokens per seconde en VRAM, geen login.

### Model

Drie vragen om de prompt scherp te krijgen:
1. Hoe wil je de data voor tokens per seconde en VRAM verkrijgen? [standaard: via de Ollama API (`/api/show` en `/api/generate` met een korte testprompt) of door logs te parseren als die beschikbaar zijn]
2. Moet het dashboard automatisch vernieuwen (bijv. elke 5 seconden) of alleen een momentopgave tonen bij het openen? [standaard: automatisch vernieuwen elke 5 seconden voor live monitoring]
3. Zijn er specifieke drempelwaarden of waarschuwingen die je wilt zien (bijv. rood wanneer VRAM > 90%) of alleen de rauwe getallen? [standaard: alleen rauwe getallen tonen, geen drempels of kleuren]

Geef je antwoorden in de vorm:  
1 ok, 2 ok, 3 alleen rauwe getallen  
of corrigeer waar nodig met een korte toelichting.

### Gebruiker

Akkoord met je voorstellen.

### Model

```
<context>
Ik wil een lokaal dashboard om mijn Ollama-modellen te monitoren op een systeem met beperkte resources (max2). Het doel is om in realtime de prestaties van geladen modellen te zien zonder in te loggen of complexe setup.
</context>

<material>
Geen externe bestanden nodig; de informatie wordt gegenereerd door de Ollama API lokaal beschikbaar op http://localhost:11434.
</material>

<task>
Bouw een eenvoudig, automatisch verversend dashboard dat de tokens per seconde en VRAM-gebruik toont voor elk momenteel geladen Ollama-model, zonder authenticatie of login.
</task>

<constraints>
- Toon alleen de rauwe getallen voor tokens per seconde en VRAM-gebruik (in MB), geen drempels, waarschuwingen of kleurcodering.
- Geen login, authenticatie of gebruikersinterface-elementen buiten de noodzakelijke weergave.
- Werk lokaal met de standaard Ollama API op poort 11434; veronderstel dat Ollama draait en toegankelijk is.
- Gebruik geen externe diensten of cloudgebaseerde monitoring.
- Het dashboard moet geschikt zijn voor snelle inspectie, niet voor langdurige logging of analyse.
</task>

<done_when>
Het dashboard toont bij elke verversing (elke 5 seconden) een lijst van geladen modellen met hun actuele tokens per seconde en VRAM-gebruik, zoals gerapporteerd door de Ollama API, zonder fouten of lege waardes wanneer modellen actief zijn.
</task>

<output_format>
Een enkel Python-script dat gebruikmaakt van Streamlit (of Gradio als Streamlit niet beschikbaar is), met duidelijke instructies voor installatie van vereiste pakketten (streamlit, requests) en het uitvoeren van het script lokaal. Het script moet zelfstandig werken na `pip install streamlit requests` en `streamlit run dashboard.py`.
</output_format>

<check_in>
Voordat het script wordt uitgevoerd, controleer of Ollama lokaal draait en toegankelijk is op http://localhost:11434. Bij twijfel, voer eerst `ollama list` uit in de terminal om te bevestigen.
</check_in>
```
Aannames:
- Ollama draait lokaal op de standaardpoort 11434 en geeft toegang tot de `/api/ps` endpoint voor geladen modellen.
- De tokens per seconde kunnen worden afgeleid uit de `prompt_eval_count` en `prompt_eval_duration` of vergelijkbare velden in de Ollama API-antwoorden, of uit een korte testgeneratie als nodig.
- VRAM-gebruik wordt gerapporteerd in de `memory_usage` of vergelijkbare veld uit de Ollama API, of kan worden afgeleid uit systeemtools als de API dit niet direct geeft.
Instellingen: effort medium.
