Hier is de prompt voor Claude Code:

```xml
<context>
Ik werk aan `agent-harness`, een Node.js/TypeScript CLI-tool. Het onderdeel `check-run-logs` controleert momenteel run-logbestanden op de aanwezigheid van geheimen (secrets) en print een mens-leesbare samenvatting.

Ik wil een `--json`-vlag toevoegen aan deze CLI, zodat de uitslag programmatisch verwerkt kan worden.
</context>

<material>
Referenties voor de bestaande code en het doel van de tool:
- Architectuur van `agent-harness`: `architecture/agent-harness.md`
- Runbook voor `check-run-logs`: `runbooks/check-run-logs.md`
</material>

<task>
Voeg een `--json`-vlag toe aan de `check-run-logs` CLI. Als deze vlag wordt meegegeven, moet de uitslag in JSON-formaat op stdout worden geprint in plaats van de huidige mens-leesbare output.

De JSON-structuur moet een array zijn van objecten, één per gecontroleerd geheim, met de volgende indeling:
[
  { "secretName": "<naam van het geheim>", "hits": <aantal gevonden hits> }
]
</task>

<constraints>
- De huidige mens-leesbare output blijft de standaard. De CLI moet volledig backward-compatible zijn.
- `--json` vereist dat er minimaal één geheim wordt gecontroleerd (dus `--config` en/of `--dir` moet aanwezig zijn).
- Foutmeldingen en debug-info moeten onveranderd naar stderr blijven gaan; alleen stdout wordt JSON.
- Voeg een unit-test toe die de JSON-uitslag valideert tegen een mock-run-log met bekende geheimen.
</constraints>

<done_when>
1. De CLI accepteert `--json` en print een geldige JSON-structuur op stdout.
2. De unit-tests voor de nieuwe JSON-functionaliteit slagen.
3. De CLI gedraagt zich exact zoals voorheen wanneer `--json` niet wordt meegegeven.
</done_when>

<output_format>
Implementeer de code in de bestaande TypeScript-bestanden. De test moet in het bestaande testframework worden geschreven.
</output_format>
```

Assumptions:
- De CLI gebruikt een standaard framework als `commander` (op basis van de `agent-harness` stack).
- De JSON-structuur is een array van objecten `{ "secretName": "...", "hits": 0 }`.
- De unit-test moet in het bestaande testframework van het project worden geschreven.
- De feature is enkel gericht op de `check-run-logs` CLI en raakt niet de rest van de tool.
