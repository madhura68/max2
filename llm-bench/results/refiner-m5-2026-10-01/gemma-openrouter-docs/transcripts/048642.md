# Transcript 048642 (D04: feit niet in de docs)

### Gebruiker

Laat de harness bij een mislukte job een melding naar ons Slack-kanaal sturen.

### Model

Om een scherpe prompt te schrijven voor Opus, moet ik eerst begrijpen hoe de harness momenteel omgaat met mislukte jobs en waar de integratie moet plaatsvinden.

Vier vragen om dit helder te krijgen:

1. Is er al een bestaand notificatiesysteem in de harness waar we op kunnen aanhaken, of moet dit volledig nieuw worden gebouwd? [standaard: volledig nieuw]
2. Welke methode voor Slack wil je gebruiken? [standaard: een Incoming Webhook URL]
3. Waar moet de Slack-URL worden geconfigureerd? [standaard: als omgevingsvariabele/environment variable]
4. Welke informatie moet in de melding staan? [standaard: job-ID, foutmelding en een link naar de logs]

**Aannames op dit moment:**
- De taak is bedoeld voor Claude Code (agent met toegang tot de bestanden), aangezien het om een wijziging in een bestaande codebase gaat.
- De harness is geschreven in de taal/stack die in de productdocumentatie van `bench-agent-harness` staat.

### Gebruiker

Akkoord met je voorstellen.

### Model

Hier is de complete prompt voor Claude Code (of Opus met toegang tot je bestanden).

```markdown
<context>
De `bench-agent-harness` is een Node 22 (ESM, TypeScript) CLI-tool die LLM-runs uitvoert. De status van een run kan `completed`, `failed`, `budget_exceeded` of `timed_out` zijn. We willen nu dat het systeem een melding naar Slack stuurt wanneer een run niet succesvol wordt afgerond, zodat we direct op de hoogte zijn van fouten in de pipeline.
</context>

<task>
Implementeer een Slack-notificatiefunctionaliteit die een bericht verstuurt via een Incoming Webhook wanneer een run eindigt met een status die niet `completed` is.
</task>

<constraints>
- Gebruik een omgevingsvariabele (bijv. `SLACK_WEBHOOK_URL`) voor de configuratie van de webhook.
- Gebruik de ingebouwde `fetch` van Node 22 voor de HTTP-aanroep naar Slack; voeg geen zware externe libraries toe.
- De melding moet de volgende informatie bevatten:
    - De Job-ID (`runId`).
    - De terminale status (`failed`, `budget_exceeded` of `timed_out`).
    - De foutmelding (indien beschikbaar in het `RunResult` object).
    - Een verwijzing naar de locatie van de logs (bijv. het pad naar `runs/<id>/trace.jsonl`).
- Zorg dat de applicatie niet crasht als de Slack-aanroep zelf mislukt (wrap in een try-catch).
- De logica moet worden geïntegreerd in de bestaande flow (waarschijnlijk in `src/run.ts` of `src/cli.ts`), op het punt waar de terminale status wordt vastgesteld.
</constraints>

<done_when>
1. De code is geïmplementeerd en de Slack-aanroep wordt getriggerd bij elke niet-succesvolle run.
2. De omgevingsvariabele is toegevoegd aan de documentatie of een `.env.example` bestand.
3. Er is een korte instructie of een test-script waarmee geverifieerd kan worden dat de melding correct wordt verzonden bij een geforceerde fout.
</done_when>

<output_format>
Pas de bestaande bestanden aan en lever een korte samenvatting van de wijzigingen en de benodigde configuratie.
</output_format>
```

**Aannames:**
- De tool draait in een omgeving waar `fetch` beschikbaar is (Node 22).
- De "link naar logs" wordt voorlopig geïmplementeerd als het lokale bestandspad, aangezien de harness een CLI-tool is.
- Je gebruikt Claude Code of een agent met directe toegang tot de `src/` map van de repository.

**Instellingen:**
- Effort: **medium**.
- Attachments: Geen (de agent leest de bestanden zelf).
