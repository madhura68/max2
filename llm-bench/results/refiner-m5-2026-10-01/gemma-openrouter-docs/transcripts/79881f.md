# Transcript 79881f (D04: feit niet in de docs)

### Gebruiker

Laat de harness bij een mislukte job een melding naar ons Slack-kanaal sturen.

### Model

Vier vragen om de prompt scherp te krijgen:

1. Moet Opus de daadwerkelijke code-wijzigingen doorvoeren, of een ontwerpvoorstel schrijven? [standaard: de code-wijzigingen schrijven]
2. Hoe moet de Slack-melding worden verzonden? [standaard: via een Slack Webhook URL]
3. Welke informatie moet er minimaal in de Slack-melding staan? [standaard: naam van de job, de reden van de fout en een link naar de logs]
4. Heeft Opus toegang tot de codebase via Claude Code, of ga je de relevante bestanden aanleveren? [standaard: toegang via Claude Code]

### Gebruiker

Akkoord met je voorstellen.

### Model

```
<context>
In de huidige opzet van de harness worden mislukte jobs niet extern gemeld. Om sneller te kunnen reageren op fouten, moet er een koppeling komen met Slack die een melding stuurt zodra een job faalt.
</context>

<task>
Implementeer in de harness een functionaliteit die een Slack-melding verstuurt via een Webhook URL wanneer een job mislukt.
</task>

<constraints>
- De melding moet de volgende informatie bevatten: de naam van de mislukte job, de reden van de fout (error message) en een link naar de logs.
- Gebruik een Slack Webhook URL voor de verzending.
- De Webhook URL mag niet hardcoded in de broncode staan, maar moet configureerbaar zijn (bijvoorbeeld via een omgevingsvariabele).
- De verzending van de melding mag de verdere uitvoering of afhandeling van de harness niet blokkeren.
- Zoek eerst in de codebase naar de plek waar jobs worden uitgevoerd en waar fouten worden afgehandeld voordat je wijzigingen doorvoert.
</constraints>

<done_when>
- De code is geïmplementeerd en de logica voor de Slack-notificatie is geïntegreerd in de failure-handler van de job.
- Er is een manier om te verifiëren (bijvoorbeeld via een test of gesimuleerde fout) dat de melding correct wordt verzonden met de juiste details.
</done_when>

<output_format>
Voer de daadwerkelijke code-wijzigingen door in de bestanden. Geef na afloop een korte samenvatting van de aangepaste bestanden en de instructies om de Webhook URL in te stellen.
</output_format>
```

**Aannames:**
- De harness heeft een centrale plek waar job-failures worden gecapt.
- Er is een geschikte manier om omgevingsvariabelen te beheren in de huidige tech-stack.

**Instellingen:**
- Effort: medium.
- Gebruik: Claude Code (voor directe toegang tot de bestanden).
