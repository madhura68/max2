### Model



Ik schrijf alleen prompts; ik beantwoord de vraag niet zelf. Hieronder vind je een prompt die je aan Opus kunt geven om het antwoord te krijgen.

```
<context>
Je werkt met het bench‑agent‑harness systeem waarin een model tools kan aanroepen (bijv. code uitvoeren, bestanden lezen/schrijven, webzoekopdrachten). Het systeem houdt bij hoeveel keer een toolaanroep fout loopt.
</context>

<task>
Leg uit wat er gebeurt wanneer het model te veel tool‑fouten maakt binnen het bench‑agent‑harness. Beschrijf de mechanismen (bijv. begrenzing, automatische uitschakeling, logging, mogelijke herstelacties) en wat de gevolgen zijn voor de lopende run of voor latere tool‑aanroepen.
</task>

<constraints>
- Gebruik uitsluitend informatie die in de officiële productdocumentatie van bench‑agent‑harness staat (of algemeen bekende gedragingen als de documentatie zwijgt).
- Als de documentatie geen specifieke grens vermeldt, geef dan aan dat dit niet is gespecificeerd en beschrijf wat het systeem volgens de algemene foutafhandeling doet.
- Beperk je antwoord tot maximaal twee alinea’s in het Nederlands.
</task>

<done_when>
Het antwoord bevat een duidelijke beschrijving van de grens‑ of limietgedragingen en de gevolgen voor het model en de run, gebaseerd op de documentatie.
</done_when>

<output_format>
Een korte toelichting van één tot twee alinea’s, geschreven in het Nederlands, zonder opsommingstekens of markdown‑opmaak.
</output_format>
```

**Aannames**
- De productdocumentatie van bench‑agent‑harness bevat een sectie over tool‑foutafhandeling of begrenzing.
- Als er geen expliciete grens wordt genoemd, valt het terug op een algemene foutlimiet die in de documentatie wordt beschreven.

**Instellingen**
- effort: medium
- Geen bijlagen nodig; Opus kan de documentatie zelf raadplegen via de beschikbare bronnen.
