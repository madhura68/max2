# Transcript f18c2c (D03: analyse van run-logs)

### Gebruiker

Ik wil de run-logs van vannacht laten nalopen op mislukte jobs.

### Model


Vier vragen om de prompt scherp te krijgen:

1. Waar staan de run‑logs van vannacht (pad of locatie) en in welk formaat zijn ze (bijv. gewone tekstbestanden, JSON‑logs, één bestand per job)? [default: één map met tekstbestanden, één bestand per job]  
2. Aan welke kenmerk(en) in een log kun je zien dat een job mislukt is (bijv. een specifieke foutmelding, exit code, statusregel)? [default: een regel met “ERROR” of “FAILED” of een exit code ongelijk aan 0]  
3. Wat wil je als resultaat zien (bijv. een lijst van mislukte job‑namen, een samenvatting met tijden, een CSV‑bestand voor verdere verwerking)? [default: een overzichtelijke lijst met jobnaam en tijdstip, afgeprint op stdout]  
4. Moet het script alleen rapporteren (read‑only) of ook acties ondernemen (bijv. verplaatsen, labelen, notificatie sturen)? [default: alleen rapporteren, geen wijzigingen]

### Gebruiker

Akkoord met je voorstellen. Het gaat om de harness-worker op max2.

### Model



**Prompt**

```
<context>
Ik wil de run‑logs van vannacht nalopen voor de harness‑worker die op host `max2` draait, om eventuele mislukte jobs te identificeren.
</context>
<material>
Volgens de specificatie *Agent‑harness M4 — harness‑runs volgen in Worker Logs* (specs/2026‑09‑28‑harness‑run‑logging‑design) worden de logs van de harness‑worker op `max2` geschreven naar de map `/worker-logs` (of een submap daarvan) als gewone tekstbestanden, één bestand per run.
</material>
<task>
Scan de logbestanden van vannacht in de harness‑worker log‑map op `max2`, bepaal welke runs zijn mislukt op basis van foutindicatoren in de logs, en geef een overzicht weer van de mislukte jobs met hun identificatie, tijdstip en korte foutmelding.
</task>
<constraints>
- Alleen logs uit de afgelopen nacht meenemen (gebaseerd op bestandswijzigingstijd of tijdstempel binnen de log).
- Een run wordt als mislukt beschouwd wanneer de log een regel bevat met “ERROR”, “FAILED” of een exit code ongelijk aan 0.
- De logs mogen alleen gelezen worden; geen wijzigingen, verplaatsingen of notificaties.
- Als een logbestand geen duidelijk tijdstempel bevat, gebruik dan de bestandswijzigingsdatum.
- Sla succesvolle runs over.
</task>
<done_when>
Het script heeft alle relevante logbestanden verwerkt en op stdout een lijst afgedrukt waarin elke regel bestaat uit:
<run_id> <timestamp> <foutmelding>
Gesorteerd op tijdstip (chronologisch). De lijst bevat alleen mislukte jobs.
</done_when>
<output_format>
Platte tekst, één mislukte job per line, velden gescheiden door een tab of komma:
<run_id><tab><timestamp><tab><foutmelding>
Geen extra koppen tenzij ze nuttig zijn. De uitkomst kan zowel in het Nederlands als Engels worden gegeven, maar de voorkeur gaat uit naar Nederlands omdat de gebruiker Nederlands sprak.
Het antwoord moet ook een korte gebruiksaanwijzing bevatten (bijv. een bash‑one‑liner of een klein Python‑script) zodat de gebruiker het direct kan uitvoeren op de machine waar de logs toegankelijk zijn.
</output_format>
<check_in>
Voordat het script wordt uitgevoerd, bevestig het pad naar de harness‑worker log‑map op `max2` (standaard: `/worker-logs`). Als de gebruiker een andere datum of locatie wil opgeven, vraag dan om bevestiging.
</check_in>
```

**Aannames**
- De harness‑worker logs staan als gewone tekstbestanden in `/worker-logs` op de host `max2` (of een bekende submap daarvan).
- Elk logbestand bevat een tijdstempel (bijv. in de bestandsnaam of aan het begin van het bestand) dat gebruikt kan worden om te bepalen of het tot vannacht behoort.
- De gebruiker heeft leestoegang tot deze bestanden vanuit de omgeving waarin het script wordt uitgevoerd (lokaal, via SSH of een gemount map).
- Het script kan worden uitgevoerd in een standaard Linux‑omgeving met gebruikelijke hulpmiddelen (grep, awk, find) of Python 3.
- Er hoeven geen wijzigingen aan de logs te worden aangebracht en er worden geen externe notificaties verstuurd; alleen rapporteren is vereist.

**Instellingen**
- effort: medium (de taak is een eenvoudige logscan zonder complexe redenering).
- Attachments: geen vereist; de relevante specificatie is reeds verwezen naar in de `<material>` sectie.

Laat het me weten als je iets wilt aanpassen aan de prompt, het pad, de foutindicatoren of het uitvoerformaat.
