# Transcript ec97d8 (D01: bouwtaak met docs)

### Gebruiker

Laat Claude Code een vlag --json toevoegen aan harness check-run-logs, zodat de uitslag als JSON op stdout komt.

### Model


Vier vragen om de prompt scherp te krijgen:
1. In welke programmeertaal of codebase staat de `harness check-run-logs` opdracht gedefinieerd? [standaard: Python in de `harness` module]
2. Welke informatie moet de JSON‑uitvoer bevatten wanneer de `--json` flag wordt gebruikt? [standaard: een object met de velden `exit_code` en `output` waarbij `output` de huidige stdout‑tekst is]
3. Moet de bestaande tekstuele output behouden blijven wanneer de flag niet wordt gebruikt, of mag deze worden vervangen door de JSON‑uitvoer? [standaard: behouden; alleen bij `--json` komt er JSON op stdout]
4. Zijn er bestaande tests voor dit commando die aangepast moeten worden, of moet ik nieuwe tests schrijven voor de `--json` functionaliteit? [standaard: bestaande tests aanpassen en één nieuwe unit‑test voor de JSON flag toevoegen]

### Model



```
<context>
De opdracht `harness check-run-logs` bestaat al in de codebase en geeft momenteel mens‑leesbare tekst op stdout. We willen een optionele vlag `--json` toevoegen die, wanneer gebruikt, de uitslag als JSON-object op stdout print i.p.v. de gewone tekst. Bij afwezigheid van de vlag blijft het bestaande gedrag ongewijzigd.
</context>

<material>
Bestand(en) waar de CLI‑commando is gedefinieerd (bijv. `src/harness/cli.py` of gelijkwaardig) en het bestaande testbestand voor dit commando (bijv. `tests/test_cli.py`).
</material>

<task>
Voeg een `--json` flag toe aan het `harness check-run-logs` commando zodat de output bij gebruik van de flag een JSON-object is met ten minste de velden `exit_code` (integer) en `output` (string, de huidige stdout‑tekst). Zorg ervoor dat zonder de flag de huidige tekstuele output behouden blijft.
</task>

<constraints>
- De flag moet optioneel zijn; de standaardgedrag (geen `--json`) verandert niet.
- Bij gebruik van `--json` mag alleen het JSON-object op stdout komen; geen extra tekst of foutmeldingen mogen worden toegevoegd tenzij het een foutafhandeling betreft (die ook als JSON moet worden uitgegeven).
- De JSON moet geldig zijn en kunnen worden geparsed met standaard `json.loads`.
- Werk bestaande tests bij zodat ze zowel de oude als de nieuwe gedragingen dekken; voeg één nieuwe unit‑test toe die specifiek de `--json` flag test.
- Gebruik alleen de Python‑standard library (bijv. `json`, `argparse`) voor de implementatie.
</constraints>

<done_when>
- Het commando `harness check-run-logs --json` produceert geldige JSON op stdout met de velden `exit_code` en `output`.
- Het commando `harness check-run-logs` (zonder flag) geeft exact dezelfde tekstuele output als vóór de wijziging.
- Alle bestaande tests slagen.
- De nieuwe unit‑test voor de `--json` flag slaagt.
</done_when>

<output_format>
Een diff‑stijl beschrijving van de gewenste wijzigingen (of de volledige bijgewerkte bestanden) inclusief:
- De aangepaste argparse‑definitie in het CLI‑bestand.
- De logica die bij aanwezigheid van `--json` de output omzet naar JSON.
- Bijgewerkte testbestanden met zowel de bestaande testcases als de nieuwe test voor de JSON‑flag.
</output_format>

<check_in>
Voordat de wijzigingen worden doorgevoerd, vraag bevestiging aan de gebruiker dat het te wijzigen bestand (bijv. `src/harness/cli.py`) correct is en dat de testlocatie (bijv. `tests/test_cli.py`) toegankelijk is. Na het aanbrengen van de wijzigingen, vraag of de gebruiker de tests wil laten draaien om te bevestigen dat alles slaagt.
</check_in>
```

- De huidige stdout‑tekst van het commando wordt teruggegeven als een string die veilig in een JSON‑waarde kan worden geplaatst.
