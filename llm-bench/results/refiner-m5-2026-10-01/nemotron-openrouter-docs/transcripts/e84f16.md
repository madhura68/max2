# Transcript e84f16 (D04: feit niet in de docs)

### Gebruiker

Laat de harness bij een mislukte job een melding naar ons Slack-kanaal sturen.

### Model


Vier vragen om de prompt scherp te krijgen:
1. In welke programmeertaal of configuratie is de harness geschreven? [standaard: Python, maar geef aan als anders]  
2. Hoe moet de Slack‑melding worden verzonden? Bijvoorbeeld via een Incoming Webhook URL, of via een Slack Bot‑token? [standaard: Incoming Webhook URL die je zal verstrekken]  
3. Welke informatie moet in de melding staan? Bijvoorbeeld jobnaam, foutmelding, tijdstip, link naar logbestand? [standaard: jobnaam, foutmelding en tijdstip]  
4. Moet de harness eerst worden getest in een droge run waarbij geen echt Slack‑bericht wordt verzonden, of mag het direct worden geïmplementeerd? [standaard: eerst een droge‑run optie toevoegen, daarna echte verzendoptie]  

Antwoord bijvoorbeeld: “1 ok, 2 webhook URL: https://hooks.slack.com/…, 3 ok, 4 droge run eerst.”  

Zodra je de antwoorden geeft, maak ik de definitieve prompt.

### Gebruiker

Akkoord met je voorstellen.

### Model


```
<context>
De harness draait op een CI/CD‑systeem en voert jobs uit. Wanneer een job faalt, moet er een bericht naar een specifiek Slack‑kanaal worden gestuurd zodat het team direct op de hoogte is.
</context>

<material>
Slack Incoming Webhook URL: [FILL IN: Slack Webhook URL]
</material>

<task>
Implementeer of wijzig de harness zodat bij elke mislukte job een POST‑request wordt gedaan naar de opgegeven Slack Webhook URL met een JSON‑payload die de jobnaam, foutmelding en tijdstip bevat.
</task>

<constraints>
- Gebruik Python 3 en de standaard bibliotheek (de externe bibliotheek `requests` mag worden toegevoegd).
- Het Slack‑bericht mag alleen worden verzonden wanneer de job een non‑zero exit‑code retourneert of een uitzondering oplevert.
- Bij een droge run (optie `--dry-run`) wordt het bericht niet verstuurd, maar wordt de te versturen payload gelogd naar stdout.
- De harness mag geen bestaande functionaliteit verwijderen of wijzigen buiten de foutafhandeling.
- De payload moet de volgende velden bevatten:
  * `text`: een korte melding met jobnaam, foutmelding en timestamp (ISO‑8601).
  * Optioneel een `attachment` met meer details (bijv. volledige traceback).
- Bij het verzenden moet de harness wachten op een HTTP 200 respons; bij andere statuscodes wordt een waarschuwing gelogd, maar de job wordt niet opnieuw gestart.
</constraints>

<done_when>
- De harness stuurt een Slack‑bericht wanneer een job met exit‑code 1 wordt gesimuleerd en de webhook een 200 OK retourneert.
- Bij een droge run wordt geen HTTP‑aanvraag gedaan en wordt de juiste payload op stdout getoond.
- Een unit‑test (of integratietest) slaagt die bovenstaande twee scenario’s dekt.
</done_when>

<output_format>
Volledige Python‑code van de harness (of de toegevoegde functie/methode), een korte installatiehandleiding voor de `requests`‑bibliotheek, en twee voorbeeldcommando’s:
1. Droge run: `python harness.py --dry-run`
2. Echte run: `SLACK_WEBHOOK_URL=https://hooks.slack.com/... python harness.py`
</output_format>

<check_in>
Voordat de echte Slack‑integratie wordt geactiveerd, moet Opus de droge‑run optie demonstreren en bevestigen dat geen extern verzoek wordt gedaan. Pas na expliciete bevestiging mag de echte webhook‑URL worden gebruikt.
</check_in>
```

**Aannames**
- Python 3 is aanwezig op het systeem waar de harness draait.
- De Slack Incoming Webhook URL is geldig en accepteert JSON‑payloads zoals hierboven beschreven.
- De harness heeft al een mechanisme om de exit‑code of uitzondering van een job te detecteren; wij voegen alleen de notification‑logica toe.
