### [BLOCKER] Cleanup can delete a foreign replacement
**Where:** `doc` §6, lines 216, 238–250; cleanup test at line 273. **Claim:** NF4 says a transfer must never delete a file that is not the app's, and cleanup removes only app-owned files. **Reality:** Ownership and cleanup are represented by `temp_path` in a pending record, and cleanup deletes whatever currently exists at that path. If the created file is removed or replaced by another process/user before error or crash cleanup, the app can delete the replacement. Route C makes this especially consequential because the recorded path is the final destination name. The path alone does not establish that the file currently there is the file MacSearch created. **Consequence:** Implementing the specified cleanup can delete a foreign file, violating the binding safety invariant. **Fix:** Before allowing cleanup to delete a path, establish that the current file is still the exclusively created file; persist and verify an appropriate stable file identity, and ensure the removal operation cannot race with replacement. Add a test that replaces the recorded file before cleanup and asserts the replacement survives.
