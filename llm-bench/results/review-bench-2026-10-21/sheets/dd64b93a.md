### [MINOR] The zero-byte orphan of Route C is never revisited, so it permanently litters the destination folder
**Where:** `sources/doc:251` (accepted restrisk), `sources/doc:237` (exclusive create on the final name), `sources/doc:250` (crash cleanup rule), F16 at `sources/doc:127-131`.
**Claim:** line 251 accepts that a crash between the exclusive create and the record insert leaves 'an empty file with no record', which 'in route C is an empty file under the destination name'. Cleanup at line 250 removes only files whose path still appears as `temp_path` in a pending record, so this file, having no record, is never cleaned.
**Reality:** The accepted trade-off covers a *half-written* app-owned file that is cleaned at the next start (NF4 line 213). The zero-byte artifact is a different case: with no record there is no `temp_path`, so the cleanup rule cannot reach it even in principle. On a later run of the same keyword and date, F16 sees this zero-byte file, the size differs from the source, so it is classified as different content and the new file is published as `naam (2).ext`. The zero-byte original stays in the destination folder indefinitely, and each further crash in the same window adds another one.
**Consequence:** Cosmetic litter in the destination folder under the final name, never corruption. It does not overwrite or delete anything, and the source is unaffected. It is also explicitly labelled accepted restrisk, so it is a disclosed limitation rather than a hidden gap.
**Fix:** SCHRAP. Leave the trade-off alone. Optionally add one sentence to line 251 noting that a zero-byte route C orphan has no record and therefore survives crash cleanup, so F16 will treat it as different content on the next run. If JP wants it gone, the smallest remedy is a sweep at startup that removes zero-length files under destination folders for runs that became `interrupted`, which is a later increment, not v1.

### [MINOR] Route A's post-rename crash window has no acceptance case, unlike its route C counterpart
**Where:** `sources/doc:220-224` (Route A), `sources/doc:269` (the route C equivalent that is tested), AC3a list at `sources/doc:257-273`.
