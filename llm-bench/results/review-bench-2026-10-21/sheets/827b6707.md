### [MAJOR] Recorded pathname is not continuing proof of ownership
**Where:** `doc`, NF4, lines 216, 229, 238, 245, 248–251; AC3a, lines 268–273.

**Claim:** Cleanup removes only the app's own files and never removes another file.

**Reality:** The ownership definition records exclusive creation and a pathname, but the schema stores no file identity and startup cleanup checks only that the recorded pathname still exists. For example: route C creates destination D, inserts a pending record with `temp_path = D`, writes half the data, and crashes. Before restart, another application or the user removes or relocates that half-file and puts a foreign file at D. Line 250 then instructs MacSearch to delete the foreign file. The same problem affects a route B temporary pathname, including its stale pathname after successful publication. Exclusive creation protects the creation operation, not subsequent pathname reuse. Immediate error cleanup also needs protection against replacement between creation and unlink.

**Consequence:** The specified mechanism violates NF4 and the binding decision forbidding deletion of foreign files. AC3a's foreign-file checks use a different pathname, so they can pass despite this defect.

**Fix:** Repair the ownership and cleanup protocol so it identifies the created object, not merely its original pathname, and fails closed when ownership cannot be safely established. Define the behavior under concurrent replacement; a non-atomic identity check followed by pathname unlink is not sufficient by itself. Leaving and reporting an uncertain orphan is preferable to deleting a foreign file. Add a crash-recovery test that replaces the recorded `temp_path` with a foreign file before restart and asserts that the replacement remains byte-for-byte intact. Preserve the accepted route C half-file trade-off.

### [MAJOR] Route C's first EEXIST retry requires a record that does not exist
**Where:** `doc`, F19b, lines 143–146; NF4, lines 218, 235–246; AC3a, line 267.

**Claim:** A retry always updates the existing record and then continues at the designated route step.

**Reality:** In route C, exclusive creation is step 2 and the pending-record insert is step 3. An EEXIST at step 2 therefore occurs before any record has been inserted. For a different-content collision, line 246 nevertheless requires updating `dest_path` in the existing record. There is no such record. F19b expressly provides an insert-if-absent rule for skipped_identical, but provides no corresponding exception for this different-content route C retry. Route C's normal continuation then reaches an insert at step 3, rather than the common retry's required update.

**Consequence:** The normative state machine cannot be followed literally for an ordinary route C collision. An implementation must invent a bookkeeping rule, or attempt an update that affects no record and potentially treat it as an error. The route C collision test only checks foreign-file preservation and absence of an unsafe rename; it can pass even if the transfer fails instead of successfully selecting a suffix.

**Fix:** Repair the retry rules with an explicit record-existence state. For route C collisions before successful exclusive creation, consume the shared attempt budget and recompute F16 without requiring a record update; insert the single pending record after successful creation. Keep the existing-record update rule for routes A and B. Extend the route C test to assert the correct final result, destination content, exactly one finalized action record on success, and no pending record. Also specify the single failed record when the attempt budget is exhausted before any successful creation.

### [MINOR] Route A disagrees with the specified conflict result
**Where:** `doc`, F16–F17, lines 131–132; NF4 route A, lines 220–224; AC3a, line 266.

**Claim:** A different-content name conflict produces `renamed`, but route A always finalizes as `moved` and its collision test expects `moved` under a suffixed name.

**Reality:** These are incompatible final-result instructions for a same-volume move that encounters a name conflict. The other routes finalize through F17, whereas route A fixes the result to moved.

**Consequence:** Implementers and tests can select different result semantics, producing inconsistent summary counts between same-volume and other transfers.

**Fix:** Repair the specification with one precedence rule. The smallest change consistent with F16 is to finalize a suffixed route A move as `renamed` and update its test expectation; mode remains available in search_run to identify it as a move.
