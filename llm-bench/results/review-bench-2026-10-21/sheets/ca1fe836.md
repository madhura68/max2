## Findings

### [MAJOR] A recorded pathname does not establish ownership of the file found there after restart

**Where:** `doc:201, 213–216, 248–251`; tests at `doc:268, 273`.

**Claim:** NF4 never deletes a foreign file. Restart cleanup deletes existing paths listed as `temp_path` in pending actions of interrupted runs.

**Reality:** Consider route C: the app exclusively creates `dest_path`, records it as `temp_path`, begins copying, and crashes. Before restart, another process removes or renames that partial file and puts a foreign file at the same pathname. The pending record still contains that path. The prescribed existence-only cleanup deletes the foreign replacement. The same problem applies to a route B temporary pathname that is replaced or reused. Neither the schema nor the cleanup rule records or validates the identity of the originally created file. The tests preserve a foreign file at a *different* pathname, so they pass even with this defect.

**Consequence:** Building the specified restart procedure can delete a file that was not created by MacSearch, violating the explicit binding protection. This is independent of the accepted partial-final-file trade-off.

**Fix:** Repair ownership tracking and cleanup: persist evidence identifying the created file, and specify a replacement-safe deletion procedure. A path existence check is insufficient, and an identity check followed by an unprotected unlink must not introduce another replacement race. If ownership cannot safely be established, leave the file untouched and report the unresolved cleanup. Add restart and live-error tests in which a foreign file replaces the app-owned file at the **same recorded pathname**, asserting that it survives unchanged.

### [MAJOR] Route C's first collision retries a record that has not been inserted

**Where:** `doc:143–146, 217–218, 235–246`; tests at `doc:265, 267`.

**Claim:** Every retry updates the existing record; no second record is inserted. Route C inserts its pending record only after exclusive creation succeeds.

**Reality:** A file can appear between F16's name selection and route C step 2. `open(...O_EXCL...)` then returns `EEXIST`, before step 3 has inserted any record. The shared retry procedure nevertheless requires updating `dest_path` in the existing record before returning to step 2. There is no such record. F19b explicitly handles a missing record for `skipped_identical`, but does not provide the corresponding no-record branch for a different-content retry or exhaustion after three failed exclusive creations. The route C collision test does not specify record count or final record state; the three-`EEXIST` case does not explicitly require execution through route C.

**Consequence:** The new route's normal collision path is not implementable literally without inventing a record lifecycle. An implementation can abort on an update of a nonexistent record or finish without the required per-file action log.

**Fix:** Explicitly distinguish retries before and after record creation. For route C before successful exclusive creation, retain the candidate and attempt counter in memory; insert the pending record once creation succeeds. If the operation instead terminates as identical or collision-exhausted, insert exactly one final `skipped_identical` or `failed` record. Keep updates for routes with an existing record. Exercise route C with different-content collision, identical collision, and three `EEXIST`s, asserting exactly one final record and no pending record.

### [MINOR] Route A assigns `moved` even when F16 requires `renamed`

**Where:** `doc:131–132, 220–224, 263, 266`.

**Claim:** Different-content conflicts produce the result `renamed`. Route A step 4 instead unconditionally sets `moved`, and its collision test expects `moved` under a suffix name.

**Reality:** The specification and acceptance tests prescribe different result classifications for a successfully suffixed same-volume move. AC3a's general different-content collision expects `renamed`, while the route A case expects `moved`.

**Consequence:** Implementers must choose which instruction to follow; history and summary counts can classify the same conflict differently by transfer route. The actual file transfer need not be wrong.

**Fix:** Make route A's final update conditional on whether F16 selected a suffix, consistent with the existing result vocabulary, and align its collision test. Alternatively define one consistent precedence rule for operation type versus renaming throughout F16/F17 and AC3a.
