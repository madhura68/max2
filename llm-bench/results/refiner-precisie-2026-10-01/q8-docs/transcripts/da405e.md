# Transcript da405e (D01: bouwtaak met docs)

### Gebruiker

Laat Claude Code een vlag --json toevoegen aan harness check-run-logs, zodat de uitslag als JSON op stdout komt.

### Model

Vier vragen om de prompt scherp te krijgen:

1. Welke JSON-structuur? [standaard: één object op stdout: `{ "checked": <aantal>, "secrets": [{ "name", "hits", "short" }], "totalHits": <som> }` — per geheim alleen naam, aantal treffers en of de waarde korter is dan 8 tekens, nooit een waarde, conform de bestaande uitdruk-regel]
2. Zonder `--json` blijft de huidige mensleesbare uitvoer op stdout ongewijzigd? [standaard: ja, de vlag schakelt alleen om]
3. Werk ook de documentatie bij na de code (manual/readme, sectie `Run-logs in Worker Logs (M4)` van runbooks/idea-chat-worker)? [standaard: ja, kort, alleen de `--json`-optie noemen]
4. Test: één geval dat de `--json`-uitvoer via `JSON.parse` valideert en de per-geheim tellingen afwijst, als onderdeel van `npm run verify`? [standaard: ja]

Aannames die ik nu al maak: de exitcodes blijven gelijk (1 bij een treffer of nul gecontroleerde geheimen, ook met `--json`); het repo `agent-harness` staat lokaal klaar (op max2: `/home/janpeter/Development/agent-harness`); de vlag heet exact `--json` en wordt gecombineerd met de bestaande `--config` en `--dir`.

### Gebruiker

Akkoord met je voorstellen.

### Model

```
<context>
Ik werk in het repo `agent-harness` (TypeScript, Node; build via `npm run build` naar `dist/cli.js`, verificatie via `npm run verify` = lint + typecheck + test, zonder netwerk). De CLI heeft al het commando `check-run-logs` (zie het runbook `runbooks/idea-chat-worker`, sectie "Run-logs in Worker Logs (M4)", en `manual/readme`, sectie "Run-logs in Worker Logs"). Het commando leest geheimen uit dezelfde vier bronnen als de redactie (`process.env`, de MCP-omgeving, `model.apiKey` en `model.baseUrl`), doorzoekt de run-logs in `--dir` recursief en drukt per geheim alleen de naam, het aantal treffers en of de waarde korter is dan 8 tekens af — nooit een waarde. Exitcode 1 bij minstens één treffer, en ook als er nul geheimen gecontroleerd zijn.

Ik wil het commando automatisch kunnen aflezen: daarom krijgt het een vlag `--json` die de uitslag als JSON op stdout zet.
</context>

<task>
Voeg aan `harness check-run-logs` de vlag `--json` toe. Met de vlag schrijft het commando in plaats van de mensleesbare tekst één JSON-object op stdout. De vlag combineert met de bestaande opties `--config` en `--dir`.
</task>

<constraints>
- Zonder `--json` verandert de bestaande mensleesbare uitvoer op stdout niet, byte voor byte.
- JSON-schema: één object `{ "checked": <aantal gecontroleerde geheimen>, "secrets": [{ "name": <naam>, "hits": <aantal treffers>, "short": <waarde korter dan 8 tekens> }], "totalHits": <som van alle hits> }`. Een waarde van een geheim komt nooit in de JSON, in argv, in stdout of in een log — dezelfde regel als de bestaande tekstuitvoer.
- De exitcodes blijven exact gelijk met en zonder `--json`: 1 bij minstens één treffer én bij nul gecontroleerde geheimen, anders 0.
- Pas de code, de tests en de documentatie aan; pas niets anders in het repo aan.
- Voeg één test toe die de `--json`-uitvoer valideert: de output parseert met `JSON.parse` en de per-geheim tellingen en `totalHits` kloppen. De test is zelfvoorzienend (geen echte service-omgeving of echte run-logs nodig) en maakt deel uit van `npm run verify`.
- Werk de documentatie kort bij: in `manual/readme` (sectie "Run-logs in Worker Logs") en in `runbooks/idea-chat-worker` (sectie "Run-logs in Worker Logs (M4)") noem je de `--json`-optie in één of twee zinnen, inclusief het JSON-schema.
</constraints>

<done_when>
- `npm run verify` is groen, inclusief de nieuwe test.
- Met `--json` is de stdout-uitvoer geldige JSON met het bovenstaande schema; zonder `--json` is de uitvoer ongewijzigd.
- De exitcodes zijn met `--json` identiek aan zonder de vlag.
- Beide documentatieplaatsen noemen de `--json`-optie.
</done_when>

<output_format>
Verwijzingen naar de bestaande broncode en tests van `check-run-logs` doorvóór je wijzigt. Lever de aangepaste code, de test en de twee documentatiestukjes, en eindig met een kort verslag van wat je hebt veranderd per bestand.
</output_format>

<check_in>
Ga door zonder te vragen, behalve als de bestaande code afwijkt van dit context-blok (andere bronnen voor geheimen, andere exitcodes, andere optiesnoemen): meld de afwijking en pas het er dan op aan. Commit en push alleen als ik dat expliciet vraag.
</check_in>
```
