# Transcript b46f20 (D04: feit niet in de docs)

### Gebruiker

Laat de harness bij een mislukte job een melding naar ons Slack-kanaal sturen.

### Model

De docs geven al een deel van het antwoord: de harness is een Node.js/TypeScript-CLI (`npm run verify` = lint + typecheck + test, `npm run build`), en in worker-modus sluit de harness jobs zelf af via `update_job_status` met `failed` en een leesbare fout (manual/readme; specs/2026-09-26-idea-chat-local-llm-design). Er staat nergens nog iets over Slack, dus de aanpak is nieuw. Vier vragen:

1. Tellen alleen jobs met eindstatus `failed`, of ook `budget_exceeded` en `timed_out`? En alleen in worker-modus, of ook een mislukte `harness run` via de CLI? [standaard: worker-modus, alle drie de eindstatussen]
2. Welke Slack-authenticatie? [standaard: een incoming-webhook URL, alleen via een omgevingsvariabele (bijv. `SLACK_WEBHOOK_URL`), zodat hij net als andere secrets nooit in de config of de trace komt — manual/readme]
3. Wat moet er in de melding staan? [standaard: job-id, jobsoort, eindstatus, de leesbare foutreden, de run-id en de worker-instance]
4. Moet het optioneel zijn via een blok in de worker-config (zoals het `workerLog`-blok), zodat zonder configuratie niets verandert? [standaard: ja]
