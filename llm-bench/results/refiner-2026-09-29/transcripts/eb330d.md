# Transcript eb330d (R03: vaag bouwidee)

### Gebruiker

Ik wil een dashboard voor mijn Ollama-modellen op max2.

### Model

Twee vragen om de prompt scherp te krijgen:

1. Wil je een zelfgebouwd webdashboard (bijv. met Python/Streamlit of Node.js) of zoek je een bestaande open-source tool die je lokaal kunt draaien? [standaard: zoek een bestaande tool en geef installatie-instructies]
2. Welke specifieke informatie moet het dashboard tonen? [standaard: lijst van modellen, status, verbruik (CPU/RAM), en mogelijkheid om modellen te starten/stoppen]

Wil je nog iets aanpassen?

### Gebruiker

Akkoord. Extra: alleen tokens per seconde en VRAM, geen login.

### Model

Ik heb nog drie vragen om de definitieve prompt te schrijven:

1. **Platform & Techniek**: Draait dit op een specifieke besturingssysteem (Windows, macOS, Linux) en heb je een voorkeur voor de bouwwijze? (Bijv. "Zoek een bestaande Docker container" vs. "Schrijf een eenvoudige Python Streamlit app"). [Standaard: Zoek een bestaande, lichte Docker-oplossing of web-app die direct met de Ollama API praat]
2. **Monitoring**: Hoe wil je de live data (tokens/sec en VRAM) ophalen? Moet de tool zelf de systeemmetrics uitlezen (via een sidecar of script) of mag het vertrouwen op wat de Ollama API al exposeert? [Standaard: De tool moet de systeemmetrics zelf uitlezen via een lichte helper, aangezien Ollama dit niet altijd live exposeert]
3. **Toegang**: "Geen login" betekent dat het dashboard puik op `localhost` (127.0.0.1) toegankelijk is via de browser, correct? [Standaard: Ja, alleen lokaal bereikbaar]

Wil je deze aannames bevestigen of iets aanpassen?

### Gebruiker

Akkoord met je voorstellen.

### Model

Hier is de voltooide prompt.

```
<context>
Ik beheer Ollama-modellen op een machine (aannames: Linux of macOS, met GPU-ondersteuning). Ik wil een lichtgewicht, lokaal dashboard dat de prestaties van actieve modellen inzichtelijk maakt, zonder ingewikkelde installaties of authenticatie.
</context>

<task>
Zoek naar een bestaande, open-source tool of geef instructies voor een eenvoudige, zelfgebouwde oplossing (bijv. een Docker-container of een korte Python/Node.js script) die als dashboard fungeert voor Ollama.
</task>

<constraints>
- De focus ligt op twee metrics: tokens per seconde (TPS) en VRAM-gebruik.
- Geen login of authenticatie; het dashboard is alleen lokaal bereikbaar (bijv. via localhost).
- De oplossing moet lichtgewicht zijn en geen zware dependencies vereisen.
- Als er geen bestaande tool is die exact aan deze eisen voldoet, ontwerp dan een minimale oplossing die de Ollama API gebruikt om actieve prompts op te halen en deze koppelt aan systeemmetrics (VRAM/TPS).
</constraints>

<done_when>
- Er is een concrete aanbeveling voor een tool (met GitHub-link of naam) OF een volledig werkbaar script/codevoorbeeld.
- Er zijn duidelijke, kopieerklare instructies voor de installatie en start.
- De documentatie vermeldt hoe je de dashboard-interface opent.
</done_when>

<output_format>
- Een korte introductie van de aanbevolen tool of oplossing.
- Stappenplan voor installatie en configuratie.
- Uitleg over hoe de metrics (TPS en VRAM) worden weergegeven.
- Eventuele beperkingen of alternatieven.
</output_format>

<check_in>
Geen check-ins nodig; lever de complete instructies in één antwoord.
</check_in>
```

Aannames:
- De machine heeft toegang tot de GPU-metrics (bijv. via `nvidia-smi` of vergelijkbaar).
- "Lokaal" betekent geen externe toegang, dus geen beveiliging over het netwerk nodig.
- De oplossing moet direct bruikbaar zijn, zonder uitgebreide setup.

Instellingen: effort medium.

Wil je nog iets aanpassen?
