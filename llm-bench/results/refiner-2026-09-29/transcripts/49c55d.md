# Transcript 49c55d (R06: review zonder bestand)

### Gebruiker

Kun je mijn docker-compose op security laten reviewen?

### Model

Een goede aanvraag. Om de review accuraat en relevant te houden, heb ik 4 details nodig:

1. Welke bestanden moet ik reviewen? [standaard: je plakt de inhoud van de `docker-compose.yaml` (en eventuele .env bestanden die je wilt tonen) direct in je antwoord]
2. Waar draait deze stack? [standaard: op een publiek bereikbare server in de cloud]
3. Wat is het doel van de review? [standaard: een lijst van kwetsbaarheden met prioritering, inclusief concrete oplossingen]
4. Zijn er specifieke compliance-eisen? [standaard: geen specifieke, focus op algemene beste praktijken en bekende Docker-kwetsbaarheden]

Zodra je dit antwoord, maak ik de definitieve prompt.

### Gebruiker

Akkoord met je voorstellen. Het is een compose-bestand voor een paar containers op mijn thuisserver.

### Model

Oké, nu ik de context heb (thuisserver, geen strikte compliance-eisen), heb ik nog één detail nodig om de prompt te maken:

1. Hoe wil je de inhoud van je `docker-compose.yaml` overdragen? [standaard: je plakt de volledige tekst direct in het volgende bericht, waarna ik de prompt genereer]

*(Optioneel: als je al weet dat je specifieke diensten zoals een database of webserver hebt die extra aandacht vragen, laat het dan weten. Anders houd ik het algemeen.)*

### Gebruiker

Akkoord met je voorstellen.

### Model

Duidelijk. Ik ga ervan uit dat je de `docker-compose.yaml` inhoud in je volgende bericht plakt. Hier is de prompt die je kunt gebruiken:

```xml
<context>
Ik heb een docker-compose.yaml bestand voor een paar containers op mijn thuisserver. Het gaat om een persoonlijke, niet-productie omgeving. Er zijn geen strikte compliance-eisen, maar ik wil wel weten of er basisveiligheidsrisico's zijn.
</context>

<material>
[PLAK HIER JE docker-compose.yaml INHOUD]
</material>

<task>
Review het bovenstaande docker-compose bestand op veiligheid.
</task>

<constraints>
- Focus op algemene beste praktijken en bekende Docker-kwetsbaarheden.
- Gebruik een thuisserver context: sommige risico's (zoals blootstelling aan het internet) zijn minder relevant als ze niet open staan, maar vermeld ze wel als potentiële risico's.
- Vermijd generic advies; wees specifiek naar de geconfigureerde services.
</constraints>

<done_when>
- Een overzicht van potentiële veiligheidsrisico's, gerangschikt op ernst.
- Voor elk risico: een korte uitleg waarom het een probleem is en een concreet advies om het op te lossen.
</done_when>

<output_format>
Een gestructureerde lijst met de gevonden issues, elk met de volgende indeling:
- **Risiko**: [Korte titel]
- **Ernst**: [Laag/Middel/Hoog]
- **Beschrijving**: [Uitleg]
- **Advies**: [Concreet advies]
</output_format>
```

**Aannames:**
- De `docker-compose.yaml` bevat geen gevoelige credentials (zoals wachtwoorden of API-keys) die je hier niet wilt delen.
- De focus ligt op configuratiefouten in de YAML (zoals `privileged: true`, `network_mode: host`, gemounte volumes, user-instellingen).

**Instellingen:**
- **Effort:** Medium (een standaard review vereist voldoende diepgang, maar geen extreem uitgebreide analyse).

Wil je nog iets aanpassen aan de prompt, of heb je de YAML-inhoud al klaar om te plakken?
