# Transcript 432ad9 (R08: agenttaak)

### Gebruiker

Laat Claude Code mijn repo migreren van Jest naar Vitest.

### Model

Zeker. Voordat ik de prompt formuleer, vier vragen:

1. Wat is de gewenste eindtoestand: alle tests draaien onder Vitest met dezelfde dekking en geen Jest-configuratie meer in het repo? [standaard: ja, volledige migratie inclusief verwijderen van Jest-afhankelijkheden]
2. Moet Claude Code zelf de wijzigingen toepassen (bestanden wijzigen, tests draaien), of alleen een migratieplan en patchen voorstellen? [standaard: zelf toepassen en de test-suite draaien tot alles groen is]
3. Zijn er bijzonderheden die Opus niet kan raden: mockings met speciale Jest-API's (bijv. jest.mock, snapshot-tests, moduleNameMapper), TypeScript-configuratie, of een CI-pipeline die ook aangepast moet worden? [standaard: geen bijzonderheden, standaard Jest-gebruik]
4. Moet Claude Code stoppen en vragen bij onzekerheden (bijv. een test die niet 1:1 over te zetten is), of doorgaan met een redelijke interpretatie en dat vermelden? [standaard: doorgaan, maar onzekerheden expliciet opsommen in een opsomming aan het eind]

### Gebruiker

Akkoord met je voorstellen. Het is een TypeScript-project met ongeveer 200 tests.

### Model

```
<context>
Ik heb een TypeScript-project met ongeveer 200 tests die nu draaien onder Jest. Ik wil de volledige test-suite migreren naar Vitest, zodat ik één moderne testrunner gebruik en de Jest-afhankelijkheden uit het project verdwijnen. De migratie wordt uitgevoerd door Claude Code, dat direct in het repo werkt.
</context>

<task>
Migreer alle tests in dit repo van Jest naar Vitest: pas de testbestanden, configuratie, mocks en helpers aan, vervang de Jest-afhankelijkheden door Vitest-afhankelijkheden, pas de npm-scripts aan, en draai de volledige test-suite tot alle tests slagen.
</task>

<constraints>
- Behoud de testdekking en de bedoeling van elke test; herschrijf tests niet louter voor de vorm.
- Zet Jest-specifieke API's over naar de Vitest-tegenhangers (bijv. jest.mock naar vi.mock, snapshots, moduleNameMapper naar aliases in de vitest-config).
- Verwijder Jest-afhankelijkheden en Jest-configuratiebestanden uit het repo nadat alles onder Vitest draait.
- Pas de TypeScript-configuratie aan waar nodig (bijv. type-definities voor test-helpers).
- Maak geen wijzigingen in productcode tenzij dat strikt nodig is om tests onder Vitest te laten draaien.
- Als een test niet 1:1 over te zetten is, kies een redelijke interpretatie en vermeld dit expliciet in een afsluitende opsomming.
</constraints>

<done_when>
- Alle 200 tests draaien onder Vitest en slagen.
- De testcommando in package.json roept Vitest aan.
- Geen Jest-afhankelijkheden of Jest-configuratie meer in het repo.
- De TypeScript-build (tsc) slaagt zonder fouten.
</done_when>

<output_format>
Na het aanpassen, draai je de volledige test-suite. Werk daarna een korte samenvatting uit met: (1) wat er is gewijzigd, (2) het resultaat van de test-run, (3) eventuele tests die niet 1:1 over te zetten waren en hoe je ze hebt aangepast.
</output_format>

<check_in>
Stop en vraag als je een test tegenkomt die fundamenteel anders gedrag vertoont onder Vitest dan onder Jest, of als productcode aangepast moet worden.
</check_in>
```

Aannames:
- Het project gebruikt een standaard Jest-setup zonder ongewone plugins of custom matchers.
- De test-suite wordt uitgevoerd via `npm test` of een vergelijkbaar script.
- Er is geen CI-pipeline die apart aangepast moet worden (of die wordt automatisch meegenomen door de wijziging van het testcommando).
- De TypeScript-versie ondersteunt de benodigde Vitest-types.
- Geen snapshot-tests die handmatig gegenereerd moeten worden.

Instellingen: effort medium. Koppel het repo aan Claude Code zodat het bestanden kan lezen en wijzigen.
