# Transcript 03d1c5 (R09: al compleet)

### Gebruiker

Ik wil een prompt voor Claude Code. Doel: een bash-script plus systemd-service en -timer voor Ubuntu 24.04 dat elke nacht om 03:00 de map /srv/backups met rsync naar mijn NAS (nas.local:/volume1/backup) synchroniseert. Het script schrijft naar /var/log/nas-sync.log, heeft een droge-run-optie (--dry-run) en verwijdert nooit bestanden op de NAS. Lever het script en de twee unit-bestanden, plus de commando's om ze te installeren en te testen. Klaar als een droge run zonder fouten loopt.

### Model

De opgave is vrij compleet. Alleen vier punten die de prompt wél veranderen:

1. Moet rsync ook bestanden verwijderen die lokaal weg zijn (dus `--delete`), of alleen kopiëren/overrijven zonder ooit iets op de NAS te verwijderen? [standaard: alleen kopiëren, dus geen `--delete` — past bij "verwijdert nooit bestanden op de NAS"]
2. Hoe verbindingsmethode naar de NAS? [standaard: SSH met `nas.local`, key-based auth, default port 22]
3. Verwacht je dat de SSH-key al geconfigureerd is, of moet het script dat ook checken/melden? [standaard: aannemen dat key-based auth werkt, script meldt bij mislukte connectie in het log]
4. Wil je ook een `rsync`-optie voor bandwidth-limitatie of parallelism, of houd je het simpel? [standaard: simpel, alleen `--archive --compress --progress`]

### Model

```
<context>
Ik gebruik Ubuntu 24.04 en wil elke nacht automatisch een backup van /srv/backups naar mijn NAS synchroniseren. De NAS is bereikbaar via SSH op nas.local (key-based auth, port 22). Ik wil geen bestanden op de NAS verwijdern; rsync mag alleen kopiëren en bestanden overwrites.
</context>

<task>
Schrijf:
1. Een bash-script (/usr/local/bin/nas-sync.sh) dat /srv/backups naar nas.local:/volume1/backup synchroniseert met rsync, logt naar /var/log/nas-sync.log, en een --dry-run-optie heeft.
2. Een systemd-service-unit (nas-sync.service) dat het script uitvoert.
3. Een systemd-timer-unit (nas-sync.timer) die de service elke nacht om 03:00 start.
4. De exacte commando's om alles te installeren, rechten te zetten, de timer te activeren en een droge run te testen.
</task>

<constraints>
- rsync mag nooit --delete gebruiken; bestanden op de NAS worden nooit verwijderd.
- rsync-opties: --archive --compress --progress.
- Het script logt met timestamp naar /var/log/nas-sync.log.
- Bij een mislukte SSH-connectie of rsync-fout: nietige exit code en een duidelijke foutmelding in het log.
- Geen bandwidth-limitatie of parallelism.
- Het script moet idempotent zijn: bij een tweede run verandert er niets op de NAS.
</constraints>

<done_when>
- Een droge run (sudo nas-sync.sh --dry-run) eindigt met exit code 0 en toont in het log welke bestanden zouden worden gesynchroniseerd, zonder dat er iets op de NAS verandert.
- De timer is geactiveerd en verschijnt in systemctl list-timers.
</done_when>

<output_format>
Vier apart gelabelde blokken:
1. Inhoud van /usr/local/bin/nas-sync.sh
2. Inhoud van /etc/systemd/system/nas-sync.service
3. Inhoud van /etc/systemd/system/nas-sync.timer
4. Installatie- en testcommando's in volgorde, elk met een korte commentaar.
Alles in één antwoord, geen extra uitleg behalve de commentaren bij de commando's.
</output_format>
```

Aannames:
- SSH-key-based auth naar nas.local werkt al; het script controleert dat niet zelf, maar meldt een fout bij mislukte connectie.
- /srv/backups bestaat al en is niet leeg.
- De NAS-destination /volume1/backup bestaat al op de NAS.
- Het script wordt uitgevoerd als root (via systemd of sudo).
